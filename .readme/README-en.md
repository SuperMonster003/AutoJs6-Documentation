## Introduction

Documentation for [AutoJs6](http://project.autojs6.com), cloned from [hyb1996/AutoJs-Docs](https://github.com/hyb1996/AutoJs-Docs/). Templates, styles and the generator originate from [Node.js](https://github.com/nodejs/node/tree/master/doc/). The online site and offline documentation plugin share one content source.

## Related projects

[AutoJs4](https://github.com/SuperMonster003/AutoJs4) is a clone of the final open-source Auto.js release `4.1.1 Alpha2`. It preserves the original source and receives the updates needed to build and run on recent Android versions. It is also the behavioral baseline of [AutoJs6](http://project.autojs6.com): apart from a few specific cases, scripts that work on AutoJs4 should work on AutoJs6 with exactly the same effects and results. AutoJs6 is a JavaScript automation tool for Android derived from Auto.js.

[AutoJs4-Documentation](https://github.com/SuperMonster003/AutoJs4-Documentation) preserves the final source of the Auto.js `4.1.0` documentation and provides the reference baseline for [AutoJs6-Documentation](http://docs-project.autojs6.com) (this project). AutoJs4 and its documentation preserve history and support behavioral comparison; AutoJs6 and this documentation maintain the current API.

## Development and publishing

`api/*.md` is the sole content source for the online and offline documentation. The Docsify site follows `master`; `targetAutoJs6Version` in `project.json` pins the reproducible offline HTML content version. After editing, the following command generates all offline HTML, applies the offline plugin's normalization rules and safely synchronizes to `AutoJs6-Plugin-Offline-Docs`. On success, this project's `versionName` and the plugin content version match `targetAutoJs6Version`, the plugin's independent release version stays unchanged, and the respective `versionCode` / `VERSION_BUILD` each increase by 1.

```powershell
generator\auto-generate-for-autojs6.bat
```

Configure the local offline-plugin path in the untracked `generator/local-config.json`; see [`generator/local-config.example.json`](http://docs-project.autojs6.com/blob/master/generator/local-config.example.json). Site builds require Python 3.10+, Node.js 16+ and npm.

`.github/workflows/pages.yml` deploys `api/` directly to GitHub Pages. Set Source to `GitHub Actions` in repository Pages Settings once, then commit and push `master` for normal updates; no `gh-pages` maintenance is needed. Pages Settings still manages the custom domain `docs.autojs6.com`. Synchronization only updates two local working trees: review and commit online documentation here; separately review, commit and release offline documentation in `AutoJs6-Plugin-Offline-Docs` following its release process.

See [`generator/README.md`](http://docs-project.autojs6.com/blob/master/generator/README.md) for generation, read-only checks, incremental builds and plugin verification commands.

## Multilingual documentation

This mechanism translates the repository README and changelog only. The API site keeps its current language. README sources are `.readme/lang_*.json` with `.readme/template_readme.md`; the root README uses Simplified Chinese. `api/changelog.md` remains the Chinese site history: synchronize changes into `.changelog/lang_zh-Hans.json`, then translate every entry into the other 9 languages, preserving versions, dated batches, entry order and links. Do not edit generated Markdown. These commands require only Python 3.10+, with no Node.js or extra Python packages; Windows can use `py` instead of `python`. `--check` writes nothing. CI validates sources, history synchronization and outputs on Ubuntu and Windows. Site generation and repository-document generation run independently.

```shell
python .python/generate_markdown.py
python .python/generate_markdown.py --check
python -m unittest discover -s .python/tests
```
