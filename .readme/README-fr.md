## Présentation

Documentation d'[AutoJs6](http://project.autojs6.com), clonée depuis [hyb1996/AutoJs-Docs](https://github.com/hyb1996/AutoJs-Docs/). Modèles, styles et générateur proviennent de [Node.js](https://github.com/nodejs/node/tree/master/doc/). Le site en ligne et le plugin hors ligne partagent la même source de contenu.

## Projets associés

[AutoJs4](https://github.com/SuperMonster003/AutoJs4) est un clone de la dernière version libre d'Auto.js, `4.1.1 Alpha2`. Il conserve les sources originales avec les mises à jour nécessaires à leur compilation et exécution sur Android récent. Il est aussi la référence comportementale d'[AutoJs6](http://project.autojs6.com): hormis quelques cas particuliers, un script fonctionnant sur AutoJs4 doit fonctionner sur AutoJs6 avec exactement les mêmes effets et résultats. AutoJs6 est un outil d'automatisation JavaScript pour Android dérivé d'Auto.js.

[AutoJs4-Documentation](https://github.com/SuperMonster003/AutoJs4-Documentation) conserve les dernières sources de la documentation Auto.js `4.1.0` et sert de référence à [AutoJs6-Documentation](http://docs-project.autojs6.com) (ce projet). AutoJs4 et ses documents préservent l'historique et permettent la comparaison; AutoJs6 et cette documentation suivent l'API actuelle.

## Développement et publication

`api/*.md` est l'unique source du contenu en ligne et hors ligne. Le site Docsify suit `master`; `targetAutoJs6Version` dans `project.json` fixe la version reproductible du contenu HTML hors ligne. Après modification, la commande suivante génère tout le HTML, applique la normalisation du plugin et synchronise de façon sûre vers `AutoJs6-Plugin-Offline-Docs`. En cas de succès, `versionName` de ce projet et la version du contenu du plugin suivent `targetAutoJs6Version`; la version indépendante du plugin est conservée, et `versionCode` / `VERSION_BUILD` augmentent chacun de 1.

```powershell
generator\auto-generate-for-autojs6.bat
```

Configurez le chemin local du plugin dans `generator/local-config.json`, non suivi par Git; exemple: [`generator/local-config.example.json`](http://docs-project.autojs6.com/blob/master/generator/local-config.example.json). La génération du site exige Python 3.10+, Node.js 16+ et npm.

`.github/workflows/pages.yml` déploie directement `api/` sur GitHub Pages. Choisissez une fois Source = `GitHub Actions` dans Pages Settings, puis validez et poussez `master` pour les mises à jour; `gh-pages` ne demande aucune maintenance. Pages Settings gère toujours le domaine `docs.autojs6.com`. La synchronisation modifie seulement deux copies de travail locales: examinez et validez le contenu en ligne ici; examinez, validez et publiez séparément le contenu hors ligne dans `AutoJs6-Plugin-Offline-Docs` selon sa procédure.

Les commandes de génération, vérification en lecture seule, compilation incrémentale et validation du plugin figurent dans [`generator/README.md`](http://docs-project.autojs6.com/blob/master/generator/README.md).

## Documentation multilingue

Ce mécanisme traduit uniquement le README et le journal du dépôt; le site API garde sa langue actuelle. Les sources README sont `.readme/lang_*.json` et le modèle `.readme/template_readme.md`; le README racine est en chinois simplifié. `api/changelog.md` reste l'historique chinois du site: reportez les changements dans `.changelog/lang_zh-Hans.json`, puis traduisez chaque entrée dans les 9 autres langues en conservant versions, lots datés, ordre et liens. Ne modifiez pas le Markdown généré. Ces commandes nécessitent seulement Python 3.10+, sans Node.js ni paquet Python supplémentaire; sous Windows, `py` peut remplacer `python`. `--check` n'écrit rien. La CI vérifie sources, synchronisation historique et résultats sur Ubuntu et Windows. Les deux générateurs fonctionnent indépendamment.

```shell
python .python/generate_markdown.py
python .python/generate_markdown.py --check
python -m unittest discover -s .python/tests
```
