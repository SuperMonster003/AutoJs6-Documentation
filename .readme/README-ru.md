## Введение

Документация [AutoJs6](http://project.autojs6.com), клонированная из [hyb1996/AutoJs-Docs](https://github.com/hyb1996/AutoJs-Docs/). Шаблоны, стили и генератор происходят из [Node.js](https://github.com/nodejs/node/tree/master/doc/). Онлайн-сайт и офлайн-плагин используют общий источник содержимого.

## Связанные проекты

[AutoJs4](https://github.com/SuperMonster003/AutoJs4) является клоном последнего открытого выпуска Auto.js `4.1.1 Alpha2`. Он сохраняет исходники с необходимыми изменениями для сборки и запуска на новых Android. Он также служит эталоном поведения [AutoJs6](http://project.autojs6.com): за редкими исключениями, скрипты AutoJs4 должны работать в AutoJs6 с теми же эффектами и результатами. AutoJs6 является производным от Auto.js инструментом автоматизации JavaScript для Android.

[AutoJs4-Documentation](https://github.com/SuperMonster003/AutoJs4-Documentation) сохраняет последние исходники документации Auto.js `4.1.0` и служит ориентиром для [AutoJs6-Documentation](http://docs-project.autojs6.com) (этого проекта). AutoJs4 и его документы сохраняют историю и позволяют сравнивать поведение; AutoJs6 и эта документация поддерживают текущий API.

## Разработка и публикация

`api/*.md` является единственным источником текста онлайн- и офлайн-документации. Сайт Docsify следует за `master`; `targetAutoJs6Version` в `project.json` фиксирует воспроизводимую версию офлайн-HTML. После редактирования следующая команда генерирует весь HTML, применяет нормализацию плагина и безопасно синхронизирует `AutoJs6-Plugin-Offline-Docs`. При успехе `versionName` этого проекта и версия содержимого плагина соответствуют `targetAutoJs6Version`, независимая версия плагина сохраняется, а соответствующие `versionCode` / `VERSION_BUILD` увеличиваются на 1.

```powershell
generator\auto-generate-for-autojs6.bat
```

Локальный путь плагина задается в неотслеживаемом `generator/local-config.json`; пример: [`generator/local-config.example.json`](http://docs-project.autojs6.com/blob/master/generator/local-config.example.json). Сборка сайта требует Python 3.10+, Node.js 16+ и npm.

`.github/workflows/pages.yml` публикует `api/` прямо в GitHub Pages. Один раз выберите Source = `GitHub Actions` в Pages Settings, затем фиксируйте и отправляйте `master`; обслуживать `gh-pages` не требуется. Домен `docs.autojs6.com` по-прежнему управляется через Pages Settings. Синхронизация обновляет только два локальных рабочих дерева: проверьте и зафиксируйте онлайн-документацию здесь; отдельно проверьте, зафиксируйте и выпустите офлайн-документацию в `AutoJs6-Plugin-Offline-Docs` по его процедуре.

Команды генерации, проверки без записи, инкрементальной сборки и проверки плагина описаны в [`generator/README.md`](http://docs-project.autojs6.com/blob/master/generator/README.md).

Документация может изменяться в любой момент и отличаться от реального поведения. ## Многоязычная документация

Этот механизм переводит только README и журнал репозитория; язык сайта API сохраняется. Исходники README: `.readme/lang_*.json` и шаблон `.readme/template_readme.md`; корневой README использует упрощенный китайский. `api/changelog.md` остается китайской историей сайта: переносите изменения в `.changelog/lang_zh-Hans.json`, затем переводите каждую запись на остальные 9 языков, сохраняя версии, датированные группы, порядок и ссылки. Не редактируйте сгенерированный Markdown. Командам нужен только Python 3.10+, без Node.js и дополнительных пакетов Python; в Windows допустимо `py` вместо `python`. `--check` ничего не записывает. CI проверяет источники, синхронизацию истории и результаты в Ubuntu и Windows. Генерация сайта и документов репозитория независима.

```shell
python .python/generate_markdown.py
python .python/generate_markdown.py --check
python -m unittest discover -s .python/tests
```
