# 3-Block Compose 设计器 (Compose 与 UI 工程)

<!-- type=misc -->

3-Block Compose 设计器是 [3-Block Compose](compose) 插件 ([AutoJs6-Plugin-Three-Block-Compose](https://github.com/SuperMonster003/AutoJs6-Plugin-Three-Block-Compose)) 自 1.2.0 起内置的可视化界面编辑器. 它在插件自己的进程中运行, 用插件的真实渲染器所见即所得地编辑 `compose` 脚本的界面树; 保存结果就是普通的 `.js` 脚本文件 (1.4.0 起也可以是 `.tsx` 文件), 可以交给 AutoJs6 运行, 也可以在 AutoJs6 编辑器中继续编写逻辑. 本页面自 3-Block Compose 1.2.0 起适用, 1.3.0 - 2.0.0 新增的能力在文中注明; 1.4.0 是插件的首个公开发行版.

本页面不是脚本 API. 设计器没有新增任何全局对象或模块, 它读写的脚本与手写的 `compose` 脚本完全相同. 脚本 API 见 [3-Block Compose](compose), 组件, 属性, 插槽与事件见 [ComposeComponents](composeComponents).

---

## 用途

- 从组件面板拖放组件, 在画布上即时看到与 AutoJs6 内一致的渲染结果, 再在属性抽屉中调整属性, 修饰链, 插槽与事件.
- 维护脚本的界面部分: 设计器只改写界面树和顶层 `compose.state` 声明, 其它语句原样保留, 因此可以反复在设计器与 AutoJs6 编辑器之间往返.
- 编辑传统 `"ui";` 模式脚本 (1.6.0): XML 布局在大纲与属性抽屉中编辑, 未触碰的字节原样保留, 画布由已安装的 AutoJs6 用 ui 模式的布局器绘制; 1.8.0 起布局也可以是单独的 XML 文件 (含 Android 原生 XML), 带布局文件的工程是一个文件夹; 1.9.0 起脚本也可以是 TSX, 布局中 `<compose>` 容器所挂的 Compose 界面也能在画布上直接编辑; 见下文 "UI (XML) 工程" 一节.
- 编辑时设计器不执行脚本: 它只解析脚本 (JavaScript 用 Rhino 解析器, TSX 用 TypeScript Engine 插件的解析服务) 并用渲染器预览, 事件处理函数不会在画布中触发, 运行要交给 AutoJs6. 1.3.0 起可以在 "状态" 面板中临时改变 state 的预览值, 并在 "交互预览" 中直接操作绑定了 state 的控件; 1.5.0 起 JavaScript 工程的交互预览会在插件内受限的沙箱中运行脚本, 见下文 "预览状态与交互预览" 一节; 1.7.0 起 UI (XML) 工程的交互预览由 AutoJs6 真实运行整份脚本 (Android 13 起), 见 "在预览中运行 UI 脚本"; 1.9.0 起配合更新的 AutoJs6, 交互预览中的对话框, 返回键, 暂停与恢复和窗口颜色更接近真实运行, TSX 脚本也能在预览中运行, 见 "交互预览的新能力".

## 工程与文件

- 工程就是一个 `.js` 文件 (1.4.0 起也可以是 `.tsx` 文件), 保存在插件私有目录 `files/designer/projects/` 中, 没有额外的工程描述文件; 1.8.0 起带布局文件的 UI 工程是一个文件夹 (`名称/main.js` 加布局文件与 `project.json`), 见下文 "XML 文件与文件夹工程". 新建工程时选择 JavaScript, TSX (1.4.0) 或 UI (XML) (1.6.0), 写入一个最小的 `compose.mount` 模板 (UI 工程为 `"ui";` 加一个带文本与按钮的 `ui.layout` 布局和一个点击处理函数); 名称重复时自动加 `-2`, `-3` 后缀. 导入的文件以 `.tsx` 结尾时成为 TSX 工程, 其它文件成为 `.js` 工程; `.js` 工程以 `"ui";` 开头且调用 `ui.layout` 时按 UI (XML) 工程读取, 首页列表以 `JS` / `TSX` / `UI` 标注类型.
- 导入: 通过系统文件选择器选择脚本, 复制为一个新工程并记录来源. 保存工程不会写回来源文件. 导出: 编辑页菜单 "导出到文件" 通过系统文件选择器另存一份. 1.8.0 起也可以导入 zip 或文件夹, 文件夹工程导出为 zip.
- 来源同步 (1.3.0): 导入时保留对来源文件的访问权限 (文件提供方允许时, 先尝试读写, 不行再只读), 之后可在编辑页菜单手动 "写回来源" 或 "从来源重新导入". 设计器记录双方上次同步时的内容摘要: 写回时来源在此之后被改过, 或重新导入时工程在此之后被改过 (含未保存修改), 都会先询问. 来源被移走, 被替换或授权失效时提示 "来源文件不可用", 可经系统文件选择器重新选择以恢复关联. 1.2.0 导入的工程没有摘要, 两侧内容相同时视为已同步.
- 外部文档: 从 AutoJs6 编辑器或文件管理器打开的文件保存时直接写回原文件. 没有写入权限时 (例如只读授权或只读路径), 保存会把内容另存为一个新工程并提示, 编辑页随即切换到该工程, 原文件保持不变.
- 草稿: 编辑停顿约 1 秒和离开编辑页时, 当前内容写入 `files/designer/drafts/`; 进程被结束后重新打开会询问恢复或丢弃草稿. 只有显式保存才写工程文件或原文件.
- 外部修改: 回到编辑页时, 如果文件已被其它程序改写 (例如 AutoJs6 编辑器刚保存), 本地没有未保存修改时自动重新加载, 否则询问重新加载还是保留本地修改.
- 图片目录 (1.3.0): 编辑页菜单 "图片目录" 为当前工程选择一个文件夹 (只读授权), `Image` 的相对路径 `src` 在其中查找并显示在画布上; 见下文 "限制" 一节.
- 插件不申请存储权限. 工程目录只通过插件自己的内容提供器, 在 "在 AutoJs6 编辑器中打开" 与 "导入 AutoJs6 脚本目录" 时按次授权给 AutoJs6, 不暴露其它目录.

本节描述 Compose 工程的编辑页; UI (XML) 工程的画布, 面板与属性抽屉见下文 "UI (XML) 工程" 一节.

竖屏时画布在上, 大纲与属性在下; 横屏或平板上 (页面宽度大于高度) 画布在左, 大纲与属性在右. 大纲与属性列表的末尾留有空白, 可以把最后几行滚动到 "+" 按钮上方.

属性抽屉中每个属性有三种状态: 字面量 (布尔, 枚举, 文本样式, 形状, 颜色, 数值, 列表与字符串各有编辑器), 绑定已声明的 `compose.state` 变量, 或保留为源码表达式 (以代码框显示, 可改回字面量). 事件列表显示处理函数的参数与源码, 可以直接编辑, 应用前做语法检查; 新增事件时生成一个空的处理函数. 修饰链是有序列表, 支持增删, 上下移与逐项参数编辑, 1.3.0 起也可以按住每项左侧的手柄拖动排序 (一次拖动是一个撤销步骤); 只对特定父容器有效的修饰项按当前父容器过滤.

承载选项对话框切换 `compose.mount`, `compose.floaty` 与 `compose.dialog`, 并按键值编辑它们的选项对象 (值按脚本字面量填写, 例如 `true`, `320`, `'rawText'`). 问题对话框列出按组件目录校验出的错误与警告 (未知属性或事件, 值类型与范围, 修饰项作用域, 子节点策略, 重复 key, 契约上限等) 以及画布无法呈现的部分, 点击条目定位到节点.

全部编辑都进入撤销 / 重做历史; 连续修改同一属性合并为一步.

1.3.0 起画布每次编辑只重新组合发生变化的节点, 约 250 个节点的文档撤销 / 重做后的刷新明显更快.

## 预览状态与交互预览

1.3.0 起编辑页有 "状态" 标签页, 画布右上角有 "交互预览" 开关; 1.5.0 起 JavaScript 工程的交互预览会运行脚本 (见下文 "在预览中运行脚本"). 两者都只改变画布, 不改动脚本, 也不产生撤销步骤或草稿.

- 状态面板列出脚本顶层的每个 `compose.state`: 名称, 脚本中的初值 (字面量或表达式源码), 以及预览值. 布尔值用开关, 数字与字符串用输入框, 其它值 (数组, 对象, `null`, 或初值是表达式时) 按 JavaScript 字面量输入. 可以单项 "重置" 或 "全部重置"; 文档被重新加载 (外部修改, 从来源重新导入) 时预览值清空.
- 画布中绑定了 state 的属性 (例如 `checked: on.value`) 显示预览值, 没有预览值时显示初值.
- 打开 "交互预览" 后画布不再点选与拖动, 组件可以直接操作; 关闭开关即回到编辑模式. JavaScript 工程 (1.5.0 起, Android 8.0 或更高版本) 运行脚本, 见下一小节. TSX 工程, 以及 Android 8.0 以下设备上的工程, 不运行脚本: 一个绑定了 state 的属性, 如果组件有一个事件的载荷字段与该属性同名, 操作就把新值写入该 state 的预览值; 目前包括 `Switch`, `Checkbox`, `RadioButton` 的 `checked`, `Slider` 的 `value`, `TextField` / `OutlinedTextField` 的 `text`, `FilterChip`, `InputChip`, `SegmentedButtonItem` 的 `selected`, `HorizontalPager` 的 `page`, `Tooltip` 与 `NavigationDrawer` 的 `open`, `SearchBar` 的 `expanded`, `DatePicker` 的 `selectedDateMillis` 与 `displayMode`, `TimePicker` 的 `hour` 与 `minute`.

不运行脚本时 (编辑模式, TSX 工程, Android 8.0 以下) 与在 AutoJs6 中真实运行的差异:

- 事件处理函数不执行. 按钮的 `onClick`, 以及处理函数中对 state 的其它赋值, 计算, `toast`, 模块调用等都不会发生; 只有上面那种 "控件的新值直接写回它绑定的 state" 会反映到预览值.
- 只有直接写成 `x.value` 的属性参与; 表达式 (例如 `selected: tab.value == 2` 或 `text: 'Hi ' + name.value`) 不会随预览值重新计算, 文本类属性仍显示其源码.
- 渲染函数不执行: 渲染前置语句, 条件与循环生成的内容仍是占位, 不会随预览值增减节点.
- 弹层由打开状态的属性决定是否画在画布中; 画布中的弹层不会因点按遮罩或返回键而关闭, 要关闭可在状态面板改回预览值.
- 预览值不随脚本保存, 也不会作为初值写回; 要改变初值, 在属性抽屉或 AutoJs6 编辑器中修改 `compose.state(...)`.

### 在预览中运行脚本 (1.5.0)

打开 "交互预览" 后, JavaScript 工程的脚本在插件内的沙箱中运行, 画布显示脚本挂载的界面. 运行的是保存时会写出的脚本, 状态面板中的预览值作为对应 `compose.state(...)` 的初值. 点击按钮, 输入文字, 拨动开关等事件交给脚本的处理函数, state 变化后渲染函数重新执行, 与在 AutoJs6 中运行时一样更新画布; 修改工程或预览值后脚本从头重新运行, 关闭开关后画布回到文档的预览. 脚本运行时, "交互预览" 开关上显示运行图标.

预览中可用的 API:

| API | 说明 |
| --- | --- |
| `compose` / `$compose` | `state`, `ref`, `modifier`, `batch`, `memo`, `createElement` 与全部节点工厂, `mount` / `floaty` / `dialog` (内容都画在画布上), `post`, `theme`, `sessions`, `version`, `isAvailable`, `ComposeError`; 节点句柄的属性读写与 `set`, `get`, `append`, `insert`, `remove`, `replace`, `clear`, `slot`, `on`, `off`, `focus`, `blur`, `scrollTo`, `edit`; 会话的 `update`, `post`, `close`, `isClosed`, `on('close')`, `showSnackbar` |
| `console`, `log`, `print`, `toast`, `toastLog` | 写入 "控制台" 标签页; `toast` 与 `showSnackbar` 也只写入控制台 |
| `setTimeout`, `setInterval`, `clearTimeout`, `clearInterval` | 同时最多 64 个待执行的定时器, 重复间隔不小于 16 ms |
| JavaScript 标准内置对象 | `JSON`, `Math`, `Date`, `RegExp`, `Map`, `Set` 等, 语言级别与 AutoJs6 的 Rhino (ES6) 一致 |

其它 AutoJs6 模块与全局函数 (`app`, `ui`, `files`, `http`, `images`, `device`, `threads`, `sleep`, `require`, `importClass` 等) 一经访问即抛出 "... is not available in the designer preview"; 需要 AutoJs6 ui 页面的 `compose.attach` 同样不可用. 脚本不能访问 Java 与 Android: `java`, `Packages`, `android` 等不可用, 也无法经任何对象取得 Java 类.

限制与差异:

- 每次进入沙箱 (加载脚本, 处理一个事件, 执行一轮到期的定时器) 最多运行约 3 秒. 超出时 (例如死循环) 预览停止脚本, 画布底部与控制台说明原因; 修改工程, 或关闭再打开交互预览即可重新运行. 脚本中的 `try` / `catch` / `finally` 不能拦截这种停止.
- 脚本错误 (未捕获的异常, `compose` 的参数错误) 显示在画布底部与控制台, 并列入问题列表; 预览继续运行, 之后的事件照常处理.
- 文本框的输入按编辑序号同步: 用户已继续输入时, 脚本基于旧内容写入的文字不会覆盖它, 与在 AutoJs6 中一致.
- `compose.memo` 在预览中每次都重新计算片段, 结果与 AutoJs6 相同, 只是不复用.
- `floaty` 与 `dialog` 的窗口选项不生效, 内容画在画布上; `AndroidView` 无法在预览中创建视图, 仍显示占位.
- 运行结果只用于画布: 不改动文档, 不写入工程或草稿, 预览中的 state 值也不会写回状态面板.
- 设计器转到后台时停止脚本, 回到前台后重新运行.
- 需要 Android 8.0 (API 26) 或更高版本 (沙箱中的 JavaScript `Date` 基于 `java.time`); 更低版本的设备与 TSX 工程按上文的方式预览, 不运行脚本.

## 可识别的脚本子集与往返规则

设计器打开脚本时只解释下面两类顶层语句, 其余顶层语句 (`require`, 函数与变量定义, 事件注册, 注释等) 按源码范围原样保留, 位置不变:

1. 顶层 state 声明: `var` / `let` / `const x = compose.state(初值)`.
2. 唯一的一处挂载调用: `compose.mount(...)`, `compose.floaty(...)` 或 `compose.dialog(...)`, 参数是返回界面树的渲染函数 (`function () { return 树; }` 或箭头函数) 或直接写出的节点, 可带选项对象; 渲染函数中 `return` 之前的语句作为渲染前置语句保留.

界面树内可识别: `compose.X({属性}, 子节点...)` 与子节点数组写法, 字符串子节点 (等价于 `compose.Text`), 快捷属性与 `compose.modifier().a().b()` 修饰链, `key`, 事件属性中的函数表达式 (源码保留), 以及对已声明 state 的 `x.value` 绑定. 属性值分三态: 字面量 (字符串, 数字, 布尔, `null`, 数组与对象字面量) 可在属性抽屉中编辑; `x.value` 识别为绑定; 其它表达式按源码保留, 画布中文本类属性显示其源码, 其它属性不参与预览. 条件或循环生成的子节点同样按源码保留, 画布中显示为占位.

以下情况无法映射, 设计器拒绝打开并给出行列位置: 语法错误, 没有挂载调用, 多处挂载调用, 根节点不是 `compose` 工厂调用, 渲染函数没有 `return`, 属性对象使用展开或计算键, 同一属性对象重复出现 `children`.

保存时按固定格式生成界面部分: 4 空格缩进, 字符串用单引号, 每个子节点独占一行. 设计器生成的脚本再次打开不会产生任何改动; 手写的脚本第一次保存时界面部分会被改写为该格式, 保留的语句与注释不变. TSX 工程见下一节 (1.2.0 与 1.3.0 不能打开 TSX 文件).

## TSX 工程

1.4.0 起设计器可以编辑 `.tsx` 工程. 新建工程时选择 "TSX", 或导入 `.tsx` 文件, 或从 AutoJs6 编辑器与文件管理器打开 `.tsx` 文件, 都按 TSX 读写. 本节说的是 `compose` 脚本; 以 `"ui";` 开头的 `.tsx` 脚本 (1.9.0) 按 UI 工程编辑, 见下文 "TSX 的 UI 工程 (1.9.0)".

- 解析: 源码交给 TypeScript Engine 插件 0.7.0 或更高版本提供的语法树解析服务 (TypeScript 解析契约 v1), 只做语法分析, 不做类型检查, 不编译, 也不执行. TypeScript Engine 首次使用该服务时需要加载 TypeScript, 打开会慢几秒, 之后通常在 1 秒内.
- 可识别的顶层语句与 JavaScript 相同 (顶层 state 声明与唯一的挂载调用), 界面树写成 JSX:
    - `<compose.X>` 与 `<compose:X>` 标签是可编辑的节点. `key`, `modifier`, 目录属性, 插槽 (属性值写成元素, 只含一个元素的 Fragment 或字符串), `slots` 与 `children` 属性, 以及 `onXxx` 事件属性中的函数都能识别.
    - 属性值: 引号字符串按 JSX 规则解码 `&amp;` 等实体, 不处理反斜杠转义; `{}` 中的字面量可在属性抽屉中编辑, `{x.value}` 识别为绑定, 其它表达式按源码保留; 不带值的属性 (例如 `enabled`) 等于 `{true}`.
    - JSX 文本子节点按 TypeScript 的 JSX 规则折叠空白, 解码实体后成为文本节点; `{'文字'}` 同样是文本节点.
    - Fragment (`<>...</>`) 被展开到所在位置; 根节点可以是只含一个 compose 元素的 Fragment.
    - 其它标签 (例如 `const Increment = compose.Button` 之后的 `<Increment>`) 与 `{}` 中的表达式子节点 (条件, 循环, 注释, 展开) 按源码保留, 画布中显示为占位.
    - `compose.state<T>(初值)` 的类型参数会保留; 带类型标注的变量 (例如 `const n: number = compose.state(0)`) 按普通语句原样保留, 不作为 state 显示. 带泛型, 返回类型, `async` 或函数名的事件函数按表达式保留.
- 以下情况拒绝打开并给出行列位置: TypeScript 报告的语法错误, 与 JavaScript 相同的结构问题, XML 标签 (例如 `<text>`) 出现在 Compose 界面中, 展开属性 `{...props}`, 带命名空间的属性名, 带参数或类型参数的渲染函数, 挂载结果变量的类型标注, 超出 Unicode 范围的数字实体.
- 生成格式: 4 空格缩进, 字符串属性用单引号 (例如 `text='Hello'`), 其它值写在 `{}` 中, 每个子元素独占一行; 没有子元素的元素自闭合, 只有一段纯文本的元素写在同一行 (例如 `<compose.Button>Add</compose.Button>`); 含单引号, `&`, 反斜杠或换行等不能原样写成 JSX 的字符串改写为 `{'...'}`; `<compose:X>` 写回为 `<compose.X>`. 设计器生成的 TSX 再次打开不会产生任何改动.
- 事件处理函数的语法检查同样由 TypeScript Engine 完成, 可以使用类型标注等 TypeScript 语法.
- 运行: "在 AutoJs6 中运行" 把工程文件以内容 Uri 交给 AutoJs6, AutoJs6 按文件名把它交给 TypeScript Engine 编译后运行 (JavaScript 工程仍交出脚本文本); 有未保存修改时先保存. 复制, 导出 (保持 `.tsx` 文件名), 在 AutoJs6 编辑器中打开与导入 AutoJs6 脚本目录与 JavaScript 工程相同.
- 未安装 TypeScript Engine, 版本低于 0.7.0, 或解析服务暂时不可用时, TSX 工程以只读方式显示源码并说明原因: 可以复制源码或重试, 不能编辑界面树, 也没有画布预览. 安装或更新 TypeScript Engine 后回到设计器会自动重试.

## UI (XML) 工程 (1.6.0)

1.6.0 起设计器可以打开传统 `"ui";` 模式脚本 (布局写成 E4X XML 字面量, 见 [ui](ui)) 并作为 "UI (XML) 工程" 编辑. 新建工程时选择 "UI (XML)", 或导入这样的脚本, 或从 AutoJs6 编辑器与文件管理器打开它, 都按 UI 工程读写; 首页列表以 `UI` 标注. 1.9.0 起脚本也可以是 `.tsx` 文件, 布局写成 JSX, 见下文 "TSX 的 UI 工程 (1.9.0)". 画布不由插件自带的渲染器绘制, 而是交给已安装的 AutoJs6 (见下文 "布局预览").

### 可识别的脚本子集

- 脚本以 `"ui";` 指令开头 (前面可以有注释), 并至少调用一次 `ui.layout(...)` (1.8.0 起或 `ui.layoutFile(...)`, 见下文 "XML 文件与文件夹工程").
- 脚本中的每个 XML 字面量都是一个布局片段: `ui.layout` 的参数 (直接写出的字面量, 或只被一个 XML 字面量初始化且之后不再赋值的变量) 是画布默认显示的根; 其它字面量 (例如 `ui.inflate` 的模板) 可以在大纲顶部的片段切换器中切换到画布.
- `ui.registerWidget(名称, ...)` 注册的自定义控件标签按脚本的约定接受任意属性, 不参与目录校验.
- 其它顶层语句 (函数, 变量, 事件注册, `require` 等) 全部按源码原样保留, 位置不变. 设计器只读写 XML 字面量, 以及 (见下文 "事件") 在 `ui.layout` 语句之后追加的处理函数桩.
- 以下情况拒绝打开并给出行列位置: 语法错误, 没有 `"ui"` 指令, 没有 `ui.layout` (或 1.8.0 起的 `ui.layoutFile`) 调用, `ui.layout` 的参数既不是 XML 字面量也不是只用一个字面量初始化的变量, 嵌套的 XML 字面量, XML 列表 (`<>...</>`), 字面量本身的 XML 语法问题.

### 无损写回

XML 字面量以带位置的具体语法树保存: 空白, 注释, CDATA, 处理指令, 属性顺序, 引号与 E4X `{表达式}` 片段全部保留, 保存时未触碰的字节不变. 只有被编辑过的开始标签 (改属性或标签名时整个开始标签重排, 未改的属性保持原文与引号, 新属性追加在末尾, 新 `id` 写在最前), 被修改的文本内容, 以及新插入的元素会被改写; 新元素按相邻元素的缩进生成并自闭合, 删除元素时连带其前面的空白行. 与 Compose 工程不同, UI 工程没有 "规范格式": 手写的脚本第一次保存也不会被整体重排.

### 编辑页

| 区域 | 内容 |
| --- | --- |
| 画布 | 由 AutoJs6 绘制的布局 (见下文 "布局预览"); 点按选中元素 (命中最小的可见元素), 长按拖到另一元素上按容器方向插入; 选中框与 "标签 #id" 标签; 缩放 75% / 100%. 画布上方一行放 "交互预览" 开关与运行状态 (1.7.0, 见下文 "在预览中运行 UI 脚本"), 1.9.0 起运行中还有 "返回键" 按钮; 1.9.0 起 `<compose>` 容器中画出所挂的 Compose 界面, 其中的节点可以点选 (见下文 "`<compose>` 容器的联动编辑") |
| 大纲 | 元素树: 折叠, 上移 / 下移 / 删除, 长按拖动到另一元素的上方 / 内部 / 下方; 脚本有多个 XML 字面量时顶部显示片段切换器, 传给 `ui.layout` 的片段标 "(ui.layout)"; 1.8.0 起布局文件以文件名列在其中, 片段行右侧的菜单 "存为 XML 文件" / "新建 XML 文件" |
| 属性 | 标签 (可换成面板中的任一标签), `id`, 文本内容 (没有元素子节点的元素), 已设置的属性 (按脚本顺序置顶), 按 View 类分组的目录属性 (最近的类展开, 简写属性在名下显示全名), 值三态, 裸属性, 任意属性名, 事件 (见下文) |
| 绑定 | 当前片段中 `{{ }}` 引用的名称: 脚本顶层字面量声明的求值结果 (`var title = "Hi"` 这类不运行脚本也能求出的声明, 在插件的沙箱中求值, Android 8.0 或更高版本), 求值失败的原因, 或 "无顶层声明"; 可以输入 JSON 覆盖值, 只影响画布, 不进文档, 撤销与草稿 |
| 问题 | 按文档站的标签与属性目录校验: 未知标签, 未知或宿主拒绝的属性, 值的类型与格式 (布尔, 整数, 尺寸, 颜色, gravity, 枚举), 只对 `relative` 子视图有效的属性, `list` / `grid` 的模板子节点, 重复 `id`, 空的 `{{ }}`; 以及布局预览的失败与诊断. 1.8.0 起其后列出脚本的 "预览差异" (见下文 "预览差异") |
| 控制台 | 布局预览时显示预览的状态与 AutoJs6 绘制时报告的失败码, 位置与诊断; 交互预览 (1.7.0) 时显示 AutoJs6 运行脚本的输出, 错误与结束原因 |
| 组件面板 | 右下角 "+": 文档站的 48 个标签按布局 / 文本 / 按钮 / 输入 / 选择 / 进度 / 图片 / 媒体 / 列表 / 其它分类, 每个带默认属性; 插入到选中的容器末尾, 或选中元素之后. 类名标签不在面板中, 脚本里已有的仍可编辑; 1.9.0 起 "Compose" 分类插入 `<compose>` 容器及其 `compose.attach` 调用 (此前 `<compose>` 容器也不在面板中); Android 原生 XML 片段 (1.8.0) 改为插入常用 View 类 |

属性值分三态: 文本 (实体在编辑器中已解码, 布尔属性是开关, 枚举属性是下拉), `{{ 表达式 }}` 绑定 (编辑花括号内的表达式, 或从顶层声明中选择; 文本与绑定混合的值编辑原文), 以及 E4X `{表达式}` (脚本运行时才有值, 只读显示源码, 可整个换成文本). 行菜单在三态之间切换, 把布尔属性写成裸属性 (`<console global>`), 或删除属性. 自由添加的属性名不在目录中时由问题列表提示, 宿主会忽略它.

### 事件

事件处理函数不在设计器中编写. 属性抽屉的 "事件" 区按标签列出事件 (所有视图: `click`, `long_click`, `touch`, `key`; 复合按钮另有 `check`; `list` / `grid` 另有 `item_click`, `item_long_click`, `item_bind`; `canvas` 另有 `draw`), 点 "添加" 后在该布局所属的 `ui.layout(...)` 语句之后 (紧随脚本已写在那里的处理函数之后) 追加:

```js
ui.ok.on('click', () => {
    // TODO
});
```

元素没有 `id` 时先按标签补一个 (`button1`), 与追加桩是同一个撤销步骤. 桩写入后就是普通源码: 设计器不再展示或修改它, 正文在 AutoJs6 编辑器中写; 脚本已经用 `ui.<id>.on(...)` 或 `.click(...)` / `.longClick(...)` 注册过的事件显示为 "脚本中已处理". 只有以语句形式传给 `ui.layout` 的布局能添加事件 (`return ui.layout(...)` 与表达式体的箭头函数不行).

### 布局预览

UI 工程的画布由已安装的 AutoJs6 绘制: 设计器把当前片段的 XML 文本 (E4X `{表达式}` 换成求得的值或源码) 与 `{{ }}` 的绑定值交给 AutoJs6 的预览服务, AutoJs6 用 ui 模式的布局器 (与 `ui.layout` 相同) 创建真实视图并画出来, 每个元素的位置回传给设计器用于点选与高亮. 不运行工程的脚本.

| 条件 | 行为 |
| --- | --- |
| AutoJs6 6.8.0 及以上, Android 11 (API 30) 或更高版本 | 画布嵌入 AutoJs6 绘制的真实视图, 编辑后约几十毫秒刷新 |
| 同上, Android 7.0 - 10 | AutoJs6 把布局画成位图传回, 画布显示快照 |
| 未安装 AutoJs6, 或 AutoJs6 低于 6.8.0 (没有预览服务) | 画布显示原因 (缺少 AutoJs6 或版本过旧), 工程仍可编辑, 大纲与属性抽屉照常 |

- 画布的逻辑屏幕与视口同大, 对应 `ui.layout` 填满页面的效果; 亮暗与语言跟随设置页.
- 布局失败 (XML 无法解析, 标签或属性被宿主拒绝, 某个 View 在测量时出错) 时画布说明原因, 问题列表与大纲定位到出错的元素; `{{ }}` 求值失败的属性按原文显示, 作为诊断列出.
- 预览运行时是 AutoJs6 内的一次 ui 模式执行, 以 "3-Block Compose 预览" 出现在 AutoJs6 的运行列表中, 可以从那里停止 (画布会提示, 回到设计器时重新连接); 设计器关闭或转到后台时释放.
- 布局预览只用于布局: 不响应控件的点击与输入 (编辑模式拦截指针), 窗口级函数 (`ui.statusBarColor` 等) 与弹出层不生效, `WebView`, `VideoView`, `SurfaceView` 类视图在快照模式下显示占位. 要在画布上真实运行脚本, 见下节 "在预览中运行 UI 脚本" (1.7.0).

### 在预览中运行 UI 脚本 (1.7.0)

画布上方的 "交互预览" 开关打开后, AutoJs6 会把整份脚本当作一次普通的 ui 模式运行来执行 (与 "在 AutoJs6 中运行" 相同的引擎, 相同的权限), 只是 `ui.layout` 的内容显示在设计器的画布上而不是 AutoJs6 的页面里. 画布里的控件直接接收点击与触摸, 脚本的事件处理函数, `{{ }}` 绑定, 定时器与其它 AutoJs6 模块都按脚本的逻辑真实运行; 控制台标签页显示脚本的 `console` 输出, 错误与结束原因. 每个工程第一次打开开关时会先确认: 这等价于运行脚本, 脚本的副作用 (文件, 网络, 无障碍操作, 悬浮窗等) 都会真实发生.

| 条件 | 行为 |
| --- | --- |
| AutoJs6 6.8.0 及以上, Android 13 (API 33) 或更高版本, 设计器 1.7.0 - 1.8.0 | 显示 "交互预览" 开关; 打开后 AutoJs6 在画布中运行脚本, 开关上显示运行图标 |
| AutoJs6 6.8.0 及以上, Android 13 或更高版本, 设计器 1.9.0 起 | 同上, 另有画布内的对话框, "返回键" 按钮, 暂停与恢复, 窗口颜色与主线程占用上限, 见下文 "交互预览的新能力 (1.9.0)" |
| Android 13 - 14 | 同上, 但画布中的输入框收不到键盘输入 (提示 "Android 15 之前预览不能接收键盘输入"); Android 15 起输入法可用 |
| Android 7.0 - 12, 或 AutoJs6 低于 6.8.0 (以及 6.8.0 正式发布前只有预览契约 v1 的测试构建) | 不显示开关, 画布上方说明原因 (需要 Android 13 / 需要更新的 AutoJs6), 用 "在 AutoJs6 中运行" 试运行脚本 |

- 运行的是保存时会写出的脚本; 绑定值面板中的临时覆盖只影响布局预览, 真实运行使用脚本自己的值.
- 修改工程后约 0.4 秒脚本从头重新运行; 关闭开关, 设计器转到后台或关闭编辑页时脚本停止, 画布回到布局预览 (1.9.0 起配合预览契约 v4 的 AutoJs6, 设计器转到后台时脚本暂停而不是停止, 见下文 "交互预览的新能力"). 脚本调用 `exit()` 或出错后结束时, 画布上方与控制台显示原因 (错误带行号), 开关保持打开, 修改工程或关闭再打开开关即可再次运行.
- 运行以工程文件名出现在 AutoJs6 的运行列表中, 也可以从那里停止.
- 运行结果只用于画布: 不改动文档, 不写入工程或草稿. 交互期间画布不再响应点选与拖拽 (指针交给脚本的控件), 大纲与属性抽屉照常可用.
- 与在 AutoJs6 中运行的差异: 没有 Activity 窗口, `activity` 为 `undefined`, `ui.finish`, `ui.statusBarColor` 等窗口级函数不生效, `ui.emitter` 为 `null` (注册 `resume`, `pause` 等事件的语句会出错); 画布的逻辑屏幕与视口同大, 没有状态栏 / 导航栏; `dialogs.*` 等对话框以悬浮窗形式显示在设计器之上 (需要 AutoJs6 的悬浮窗权限). 脚本体与处理函数和真实运行一样在 AutoJs6 的主线程执行, 忙等 (例如 `while (true)`) 会卡住 AutoJs6, 停止也要等它让出; 定时器与事件驱动的脚本可随时停止. 1.9.0 起配合预览契约 v4 的 AutoJs6, 对话框, `ui.emitter`, 状态栏 / 导航栏颜色与主线程忙等的差异缩小, 见下文 "交互预览的新能力 (1.9.0)" 与 "预览差异".
- 与 JavaScript (Compose) 工程的交互预览不同, UI 工程的脚本不在插件内的沙箱里运行, 而是真实地在 AutoJs6 中运行, 没有 API 范围与时间限制; 不要在预览中运行会产生不可逆副作用的脚本.

### 交互预览的新能力 (1.9.0)

1.9.0 起, 已安装的 AutoJs6 包含预览契约 v4 (AutoJs6 6.8.0 及以上, Android 13 或更高版本) 时, 交互预览更接近在 AutoJs6 中运行:

- 对话框: `dialogs.*`, `dialogs.build(...)` 与全局的 `alert`, `confirm`, `prompt`, `rawInput` 弹出的对话框画在画布内, 可以直接点按; 不再以悬浮窗显示在设计器之上, 也不需要悬浮窗权限.
- 返回键: 运行中画布上方显示 "返回键" 按钮. 按下时先交给打开的对话框 (与真实窗口一样处理, 例如关闭可取消的对话框), 没有对话框时交给脚本 `ui.emitter` 的 `back_pressed` 事件 (处理函数调用 `e.consume()` 或设置 `e.consumed = true` 即为已处理); 都没有处理时, 这次运行像页面被关闭一样结束, 画布上方与控制台显示结束原因.
- 暂停与恢复: `ui.emitter` 在预览中可用, 运行开始时收到 `create`. 设计器转到后台时脚本收到 `pause` 并继续运行, 回到设计器时收到 `resume`, 不再从头重新运行; 关闭开关或关闭编辑页时脚本停止. 修改工程后仍按原来的方式从头重新运行.
- 窗口颜色: `ui.statusBarColor` 与 `ui.navigationBarColor` 设置的颜色显示为画布顶部 24 dp 与底部 48 dp 的色条, 布局在两者之间; `ui.backgroundColor` 填充画布. `ui.finish`, `ui.keepScreenOn` 与状态栏 / 导航栏图标函数仍不生效, 控制台给出提示.
- 主线程占用上限: 设置页 "设计器" 分组新增 "主线程占用上限" (1, 2, 3, 5, 10, 15, 30 或 60 秒, 默认 5 秒). 脚本持续占用 AutoJs6 的主线程超过该时长 (例如主线程上的 `while (true)`) 时, AutoJs6 停止这次运行, 画布上方与控制台显示 "AutoJs6 停止了脚本: 它占用主线程超过 5 秒 (第 12 行)" 这样的说明, 设计器不会被卡住. 只统计脚本自身的指令: 卡在一次原生调用中的脚本不会被打断, 定时器与其它线程不受影响.

第一次打开开关时的确认说明随之改为 "关闭开关或关闭编辑页时脚本停止; 设计器在后台时脚本会像应用一样收到 pause, 回到前台时收到 resume". 已安装的 AutoJs6 是 6.8.0 正式发布前的测试构建 (预览契约 v2 / v3) 时这些都不出现, 交互预览保持 1.8.0 的做法: 设计器转到后台即停止脚本, 回来时从头重新运行, 设置页的上限被忽略. 问题标签页中的预览差异随之缩小, 见下节.

### 预览差异 (Preview Differences)

1.8.0 起, UI 工程的 "问题" 标签页在校验问题与布局预览的问题之后列出 "预览差异": 设计器解析脚本 (不运行) 时找出在预览中运行与在 AutoJs6 中运行行为不同的写法, 每条显示行号, 该行用到的写法与一句说明. 它们是信息级提示, 不计入菜单 "校验结果" 中的错误数, 也不影响保存与运行; 点按条目会在浏览器中打开本节. 布局预览不运行脚本, 说明描述的是交互预览运行脚本时的行为.

1.9.0 起差异按已安装的 AutoJs6 的能力列出. 下表中间一列是较旧的 AutoJs6 (预览契约 v2 / v3, 只出现在 6.8.0 正式发布前的测试构建中) 上的行为; 右列是包含预览契约 v4 的 AutoJs6 (6.8.0 及以上, Android 13 或更高版本) 上的行为, 标为 "不再列出" 的写法在这样的 AutoJs6 上不出现在问题标签页中.

| 写法 | 较旧的 AutoJs6 (预览契约 v2 / v3) | 包含预览契约 v4 的 AutoJs6 (1.9.0 起) |
| --- | --- | --- |
| `activity.*` | 预览没有 Activity 窗口, `activity` 不可用, 运行到这一行时出错 | 相同 |
| `ui.emitter` 监听 `resume`, `pause` 或 `back_pressed` | 预览中 `ui.emitter` 为 `null`, 运行到这一行时出错; 这些事件只在 AutoJs6 中运行时发生 | 不再列出: 设计器转到后台与回来时发生 `pause` 与 `resume`, "返回键" 按钮发生 `back_pressed` |
| `ui.emitter` 的其它用法 (`activity_result`, `create_options_menu`, `options_item_selected` 等事件) | 同上; Activity 事件只在 AutoJs6 中运行时发生 | 注册不再出错, 但预览中的 `ui.emitter` 只会收到 `create`, `resume`, `pause` 与 `back_pressed`; 其它 Activity 事件只在 AutoJs6 中运行时发生 |
| `ui.statusBarColor`, `ui.navigationBarColor`, `ui.backgroundColor` | 预览没有窗口, 调用不生效 | 不再列出: 状态栏与导航栏颜色显示为画布上下的色条, 背景色填充画布 |
| `ui.finish`, `ui.keepScreenOn`, `ui.statusBarIconLight`, `ui.statusBarIconLightBy`, `ui.navigationBarIconLight`, `ui.navigationBarIconLightBy` | 同上; `ui.finish` 不会结束这次运行 | 相同 |
| `dialogs.*` 与全局的 `alert`, `confirm`, `prompt`, `rawInput` | 对话框以悬浮窗显示在设计器之上而不是画布内, 并且需要 AutoJs6 拥有显示在其他应用上层的权限 | 不再列出: 对话框画在画布内, 不需要悬浮窗权限 |
| 主线程上的无限循环: 条件恒为真的 `while`, `do ... while` 或没有条件的 `for (;;)`, 循环体内没有能离开它的 `break`, `return` 或 `throw`, 且不在交给 `threads.start` 的函数中 | 与真实运行一样在 AutoJs6 的主线程执行; 在预览中会卡住 AutoJs6, 设计器也无法停止这次运行. 把这类循环放进 `threads.start(...)` | 不再列出: 占用主线程超过设置页的 "主线程占用上限" 时 AutoJs6 停止这次运行并显示所在行 |
| `threads.*`, `events.*` | 交互预览中与在 AutoJs6 中一样真实运行, 预览停止时随之结束 | 相同 |

- 脚本自己声明了同名的变量, 函数或参数 (例如 `let events = []`) 时, 该名称不作为差异列出.
- 同一行的同一类差异只列一条. 列表只看写法, 不判断这一行运行时是否会被执行到.
- 输入法与弹出层的 Android 版本限制见上文 "在预览中运行 UI 脚本" 的条件表, 不在差异列表中.

### XML 文件与文件夹工程 (1.8.0)

1.8.0 起 UI 工程的布局可以写在单独的 XML 文件里, 由脚本以字符串字面量路径引用:

| 写法 | 含义 |
| --- | --- |
| `ui.layoutFile("layout.xml")` | 该文件作为页面布局 (与 `ui.layout` 相同), 画布默认显示它; 片段切换器以文件名标注 |
| `ui.inflate(files.read("item.xml"), ...)` | 该文件作为另一个片段 (例如列表项模板) |
| `ui.useAndroidLayout()` / `ui.useAndroidLayout(true)` / `ui.useAndroidLayout(false)` | 布局按 Android 原生 XML / AutoJs6 XML 解析; 不写时按内容判断 (根元素声明命名空间或使用 `android:` / `app:` 属性即为原生), 与 AutoJs6 的判断相同 |

- 路径相对脚本所在的文件夹; 拼接或变量给出的路径不读取. 读不到的文件在问题标签页列出, 画布不显示它; 脚本唯一的布局读不到时拒绝打开并说明原因.
- 文件片段与脚本内的 XML 字面量一样无损编辑: 文件开头的 BOM, XML 声明与注释, 根元素之后的内容原样保留, Windows 换行在写回时还原. 保存与草稿只写有改动的文件. 事件桩追加在加载该文件的语句之后.

#### 新建 XML 文件

大纲顶部片段行右侧的菜单提供两种做法, 都是一个可撤销的编辑步骤, 保存时才写文件:

- "存为 XML 文件": 把当前片段原样移到文件, 脚本中的 `ui.layout(<...>)` 改为 `ui.layoutFile("...")`, `ui.inflate(<...>, ...)` 改为 `ui.inflate(files.read("..."), ...)`. 只有直接写在 `ui.layout(...)` 中或作为 `ui.inflate(...)` 第一个参数的字面量可以移动; 经变量传递的字面量与含 E4X `{表达式}` 的字面量不行 (文件中的 `{...}` 不会被求值).
- "新建 XML 文件": 新建只含一个纵向根容器的文件, 可选 AutoJs6 XML 或 Android 原生 XML (脚本已写明 `ui.useAndroidLayout` 时随之, 不再询问), 并在脚本末尾追加 `let <名称>View = ui.inflate(files.read("..."));`.
- 路径须是以 `.xml` 结尾的相对路径, 不能离开脚本所在的文件夹, 不能与脚本已引用的文件重名; 原生 XML 默认放在 `res/layout/` 下.

#### 文件夹工程

- 私有工程第一次带着布局文件保存时, 由 `名称.js` 变为文件夹 `名称/`: 脚本改名为 `main.js`, 布局文件放在同一文件夹中, 草稿, 来源记录与图片目录随之迁移, 并生成 AutoJs6 的 `project.json` (`name`, `main`, `packageName` 为 `org.example.<名称>`, `versionName`, `versionCode`), 因此在 AutoJs6 中可以作为项目运行与打包. 首页以 `名称/` 显示文件夹工程.
- 新建工程时, UI 类型的 "布局" 可选 "脚本内", "AutoJs6 XML 文件" 或 "Android 原生 XML 文件"; 后两种直接创建文件夹工程, 原生模板为 `ui.useAndroidLayout()` 加 `res/layout/activity_main.xml`, 与 AutoJs6 示例 "Android 原生布局" 的组织方式相同.
- 菜单 "导出到文件" 把文件夹工程 (或带布局文件的文档) 导出为一个 zip: `main.js` 在顶层, 缺少 `project.json` 时补上.
- 首页菜单 "导入脚本或 zip" 也接受 zip, "导入文件夹" 接受一个文件夹: 顶层 (或唯一外层文件夹内) 有 `main.js` 时成为文件夹工程; 没有时, 唯一的顶层 `.js` 改名为 `main.js`; 只有一个脚本时成为普通工程. 含不安全路径 (`..`, 绝对路径), 超过 4096 个文件或 128 MB, 或找不到脚本的 zip 整体拒绝. 导入的 zip 与文件夹不记录来源.

#### 外部文档

从 AutoJs6 编辑器或文件管理器打开的脚本, 布局文件在脚本所在的文件夹中读写. 以文件路径 (`file://`) 打开时直接读写; 以内容 Uri 打开 (例如 AutoJs6 编辑器交来的脚本) 时, 第一次需要在系统文件夹选择器中选择脚本所在的文件夹 (问题标签页, 读不到布局时的报错页, 或布局文件菜单中的 "选择脚本所在的文件夹以读写布局文件"), 设计器核对其中有该脚本后保留读写授权, 之后按需在其中创建子文件夹与文件. 没有写入权限的文档另存为工程时, 布局文件一同存入新的文件夹工程.

#### 预览中的工程文件

布局预览与交互预览把工程文件交给 AutoJs6: 文件夹工程的全部文件, 外部文档旁的 `res/` 目录, 以及设计器中尚未保存的布局文件. 因此布局可以引用 `res/` 中的字符串, 颜色, 尺寸, 样式, 图片与 `<include>` 布局 (见 [用户界面](ui) 的 "工程资源"), 交互预览中的 `ui.layoutFile` 与 `files.read` 按工程目录解析. 这需要预览契约 v3 (AutoJs6 6.8.0 及以上); 6.8.0 正式发布前只有更早契约的测试构建只收到 XML 文本, 问题标签页提示 res 资源与布局文件的预览可能与实际运行不同.

#### Android 原生 XML

原生片段按 AutoJs6 实际处理的属性目录编辑与校验. 目录由宿主的属性表与设备覆盖快照生成 (见 [Android XML 属性](uiAndroidAttributes)), 列出每个 View 类可设置与不能设置的 `android:` / `app:` 属性, 以及各父布局接受的布局参数:

- 属性抽屉: id 写作 `android:id="@+id/..."`; 按类与父布局列出可设置的属性, 布尔属性为开关, 纯枚举属性为下拉; 标签不能在抽屉中改换.
- 组件面板: 插入常用的 View 类 (`LinearLayout`, `TextView`, `Button`, `EditText`, `ImageView` 等, 带 `android:layout_width` / `android:layout_height`).
- 问题标签页: 缺少 `android:` / `app:` 前缀的属性 (原生 XML 会忽略它), 未知属性, 不是父布局参数的布局属性, AutoJs6 不能设置的属性, 以及值的格式 (布尔, 整数, 尺寸, 颜色, 枚举与标志名); `@` / `?` 引用不检查.

### TSX 的 UI 工程 (1.9.0)

1.9.0 起 UI 工程也可以是 `.tsx` 脚本: 以 `"ui";` 开头, 布局写成 JSX, 由 AutoJs6 交给 TypeScript Engine 编译后运行. 新建工程时选择 "UI (XML)" 并把 "布局" 选为 "TSX 脚本内", 或导入 / 打开这样的 `.tsx` 文件, 都按 TSX 的 UI 工程读写. 读取 TSX 需要 TypeScript Engine 0.7.0 或更高版本; 未安装时与 TSX 工程一样只能查看与复制源码. 新建工程的模板:

```tsx
"ui";

ui.layout(
    <vertical padding='16'>
        <text id='title' text='Hello' textSize='24sp' />
        <button id='ok' text='OK' onClick={() => {
            toast('OK');
        }} />
    </vertical>
);
```

- 片段: `ui.layout(...)` 与 `ui.inflate(...)` 的 JSX 实参, 以及用 `const` / `let` 声明的 JSX 变量都是布局片段, 与 JavaScript 脚本中的 XML 字面量一样在大纲顶部切换; 经变量交给 `ui.layout` 的是画布默认显示的根. 组件面板, 属性抽屉与问题标签页与 JavaScript 的 UI 工程相同.
- 属性值: 引号字符串与 `{'...'}` 中的字符串可以编辑; `{16}`, `{true}`, `{-1}` 这类数字与布尔字面量在预览中使用其值; 其它 `{表达式}` 只读显示源码. 不带值的属性等于 `true`.
- 以下写法 AutoJs6 运行 TSX 时不接受, 设计器拒绝打开并给出行列位置: `ui.layoutFile`, 布局中的 `<compose.X>` 标签, 属性展开 `{...props}`, 同名属性, 有两个根的片段, 被重新赋值的 JSX 变量, 不是 JSX 的 `ui.layout` 实参; 语法错误同样给出行列位置.
- 写回: 没有改动的片段原样保留; 改动过的片段整体按统一格式重写 (4 空格缩进, 每个子元素一行, 字符串属性用单引号, 不能原样写的值写成 `{'...'}`, 没有子元素的元素自闭合). 与 JavaScript 的 UI 工程逐字节保留不同, TSX 片段一经编辑就整体重排; 新建模板已是这一格式.
- 事件桩: 点击写成元素上的 `onClick={() => { ... }}`; 其它事件在布局语句之后追加 `(ui as any).<id>.on('<事件>', (_event: any, _view: any) => { ... });`, 因为 `ui.<id>.on(...)` 在 TypeScript 严格模式下不能通过编译. 元素上只允许 `onClick` 这一个事件属性, 其值须为函数.
- 预览: 布局预览把 JSX 转成 XML 交给 AutoJs6 (不含 `onClick`); 交互预览见下文.
- 运行与导出: "在 AutoJs6 中运行", 导出与导入 AutoJs6 脚本目录都保持 `.tsx` 文件, AutoJs6 按文件名交给 TypeScript Engine 编译. 布局文件 ("存为 XML 文件", "新建 XML 文件") 只对 JavaScript 脚本提供.

#### 在交互预览中运行 TSX

已安装的 AutoJs6 包含预览契约 v5 (AutoJs6 6.8.0 及以上) 并且装有 TypeScript Engine 0.7.0 或更高版本时, TSX 的 UI 工程也可以打开 "交互预览": AutoJs6 先用 TypeScript Engine 编译脚本再运行, 编译期间画布上方显示 "TypeScript Engine 正在编译 TSX 脚本".

- 编译失败时画布上方显示第一个错误, 例如 "TSX 脚本未通过编译 (第 7 行): ...", 点按可在控制台查看全部错误; 修改工程后重新编译.
- 运行中出错时显示的行号是 TSX 文本中的行号.
- 不满足条件时开关保持关闭并说明原因: AutoJs6 较旧时为 "当前的 AutoJs6 还不能在交互预览中运行 TSX 脚本", 没有 TypeScript Engine 时为 "交互预览运行 TSX 脚本需要 TypeScript Engine 插件"; 两种情况都可以用 "运行" 在 AutoJs6 中试运行.
- 其它行为与 JavaScript 的 UI 工程相同, 包括上文 "交互预览的新能力 (1.9.0)" (契约 v5 的 AutoJs6 同样具备契约 v4 的能力).

### `<compose>` 容器的联动编辑 (1.9.0)

AutoJs6 的 ui 模式可以在布局中放置 `<compose>` 容器, 再用 `compose.attach(ui.<id>, ...)` 把 Compose 界面挂在其中 (见 [3-Block Compose](compose)). 1.9.0 起设计器把这样的界面画在画布上容器所在的位置, 并可以就地编辑:

```js
"ui";

let count = compose.state(0);

ui.layout(
    <vertical padding="16">
        <text id="title" text="Header"/>
        <compose id="panel" w="*"/>
    </vertical>
);

compose.attach(ui.panel, function () {
    return compose.Column({padding: 16},
        compose.Text({text: "Panel"}),
        compose.Button({onClick: () => { count.value++; }},
            compose.Text({text: "Add"})));
});
```

- 识别: 脚本中 (XML 字面量之外) 的 `compose.attach(ui.<id>, <界面>)`, 也认 `$ui.<id>`, TSX 中为 `(ui as any).<id>`; 第二个参数是渲染函数或直接写出的节点, 按 Compose 工程的规则读取 (见上文 "可识别的脚本子集" 与 "TSX 工程"). 写在 XML `{表达式}` 中或另一个界面内的调用留给外层. 读不出的调用 (例如经 `ui.findView(...)` 变量指定容器, 或同一容器的第二个调用) 保持原文, 问题标签页列出原因; 没有 id 相同的 `<compose>` 元素时也会列出.
- 画布: AutoJs6 照常排布 `<compose>` 元素, 设计器在元素的边界内用插件的渲染器画出所挂的界面 (从左上角起, 与元素同宽, 超出的部分裁掉). 没有自己高度的 `<compose>` 元素 (未设高度或为包裹内容, 且没有 `minHeight`) 在布局预览中按界面的高度占位, 其后的元素随之下移, 与运行时一致; 保存的脚本不变.
- 选择与编辑: 点按先命中最上层界面中最深的 Compose 节点, 其次才是其下的 XML 元素; 选中框的标签为 `类型 #key`. 选中带界面的 `<compose>` 元素或其中的节点时, 抽屉换成 Compose 工程的面板 (属性, 插槽与状态), "返回布局" 回到布局的面板. 状态标签页可以改 `compose.state` 的预览值, 只影响画布.
- 撤销与保存: 界面的编辑与布局的编辑在同一撤销历史中. 保存时只重写 `compose.attach` 的第二个参数: 没有改动的界面原样保留, 改动过的按 Compose 工程的统一格式写出 (续行按调用所在行缩进); 调用的其余部分与脚本其它文字不变. 会改到界面之外的编辑 (例如新增 `compose.state` 声明) 被拒绝, 而不是在保存时丢失.
- 新建容器: 组件面板的 "Compose" 分类一步插入 `<compose id='compose1' w='*'/>`, 并在布局语句之后 (已有的事件桩之后) 追加 `compose.attach(ui.compose1, function () { return compose.Column(...); });` (TSX 为 `(ui as any).compose1` 与箭头函数), 初始界面是一个含文字 "Compose" 的 `Column`, 插入后直接在抽屉中打开. 这是一个可撤销的编辑步骤, 保存时才写入文件. Android 原生 XML 片段中不提供; 布局语句之后没有放调用的位置时 (例如 `return ui.layout(...)`) 不插入并说明原因.
- 交互预览不叠画: 运行时由 AutoJs6 真实执行 `compose.attach`, 画布上是运行中的界面, 可以直接点按.

### 限制

- 只识别 `"ui"` 指令, XML 字面量 (TSX 脚本中为 JSX, 1.9.0) 与以字符串字面量引用的布局文件 (1.8.0); 用字符串拼接或运行时才生成的布局不在画布中.
- `<compose>` 容器的联动编辑 (1.9.0) 只识别直接以 `ui.<id>` 指定容器的 `compose.attach` 调用, 每个容器一个界面; 界面的读法与 Compose 工程相同, 读不出的部分以占位呈现或使调用保持原文.
- 布局预览不运行脚本: `{{ }}` 只能显示顶层字面量声明或绑定值面板给出的值; 列表项模板中的 `{{ }}` 没有数据源, 按原文显示. 交互预览 (1.7.0, Android 13 起) 运行整份脚本后这些都按脚本的逻辑显示.
- 布局预览需要 AutoJs6 的预览服务; 旧版本 AutoJs6 只能编辑, 不能预览.
- 属性目录来自文档站 (`ui` 与 `uiAttributes` 页面, 生成时的文档提交记录在目录中), 文档未收录的属性按 "未知属性" 提示而不是拒绝. Android 原生 XML 片段 (1.8.0) 使用由宿主属性表生成的另一份目录, 见上文 "Android 原生 XML".

## 与 AutoJs6 的衔接

编辑页菜单提供四个去向, 都复用 AutoJs6 的公开入口, 需要已安装 AutoJs6; 去向前如有未保存修改会先保存:

| 去向 | 行为 |
| --- | --- |
| 在 AutoJs6 中运行 | 把脚本文本交给 AutoJs6 运行, 与组件画廊的 "运行" 相同; TSX 工程 (1.4.0) 与 TSX 的 UI 工程 (1.9.0) 交出工程文件, 见上文 "TSX 工程" 一节; 带布局文件的 UI 工程 (1.8.0) 交出工程 zip, AutoJs6 解到缓存目录并以项目方式运行, 结束后清理 |
| 在 AutoJs6 编辑器中打开 | 以内容 Uri 和读写授权在 AutoJs6 编辑器中打开同一文件; AutoJs6 保存后回到设计器会自动重新加载 |
| 导入 AutoJs6 脚本目录 | AutoJs6 以文件名把脚本复制到自己的脚本目录; 带布局文件的 UI 工程 (1.8.0) 交出工程 zip, AutoJs6 解到脚本目录下与 zip 同名的文件夹, 已存在时询问覆盖 (zip 中的文件替换同名文件, 其它文件保留) 或另存为新文件夹 |
| 复制脚本 | 复制到剪贴板 |

反向交接由 AutoJs6 编辑器发起: 编辑器 "更多" 菜单中的 "在 3-Block Compose 设计器中打开" (或下文布局预览面板上的同名按钮) 先保存当前文件, 再以读写授权交给设计器; 设计器保存后回到 AutoJs6 编辑器, 编辑器按文件内容是否变化自动重新加载, 存在未保存修改时先询问. 已安装的插件低于 1.2.0 或未安装时不显示该入口.

本页提到的 AutoJs6 能力都需要 AutoJs6 6.8.0 及以上: 上表的四个去向, 反向交接, UI 工程的布局预览与交互预览 (含 1.9.0 的新能力), 带布局文件的 UI 工程的运行与导入 (1.8.0), 以及下文的编辑器布局预览; 在交互预览中运行 TSX 另需 TypeScript Engine 0.7.0 或更高版本. 低于 6.8.0 的 AutoJs6 上, 带布局文件的 UI 工程的运行与导入换成一行 "需要更新版本的 AutoJs6", UI 工程的画布说明原因. 6.8.0 正式发布前的测试构建只具备其中一部分能力, 设计器按其实际能力降级, 见上文各节.

设计器本身不依赖 AutoJs6: 画布使用插件自带的渲染器, 与脚本在 AutoJs6 内运行时的渲染实现相同.

### AutoJs6 编辑器中的布局预览

AutoJs6 6.8.0 起, AutoJs6 编辑器自己也能预览 ui 模式脚本的布局, 不必打开设计器. 它与设计器的布局预览使用同一套 ui 模式布局器, 但只读取脚本, 不编辑布局:

- 开关: 编辑以 `"ui";` 开头的 `.js` 脚本时, 编辑器工具栏显示 "预览" 开关. 打开后编辑区一分为二: 竖屏时预览在下半区, 横屏时在右半区. 开关按文件记住, 再次打开同一文件时恢复. TSX 脚本, Node.js / Bun / QuickJS 脚本与以大文件模式打开的文件不显示该开关.
- 布局: 预览显示源码中第一个 `ui.layout(...)` 调用的布局, 实参须为 XML 字面量, 或只被一个 XML 字面量初始化且没有重新赋值的变量. 布局按整个窗口的尺寸排布 (与脚本运行时自己的页面一致), 再等比缩小放进预览区并居中. 停止输入约 0.4 秒后刷新.
- 定位: 点按预览中的控件, 编辑器光标跳到该元素开始标签所在的源码行, 控件显示高亮框.
- 不运行脚本: 预览只解析源码, 不执行脚本的任何部分, 事件处理函数, 定时器与其它语句都不会运行 (预览区标注 "仅布局, 不运行脚本"). XML 中的 `{表达式}` 与 `{{ }}` 绑定只在安全作用域内求值: 只能使用字面量, 脚本中初始化为字面量的顶层声明, 少量无副作用的标准全局对象, 属性读取, 运算符, 条件与方法调用; 函数, 赋值, `new` 以及通往构造函数的属性在求值前即被拒绝, 调用 `files`, `shell` 等模块的表达式也不会执行. 不能求值的属性按原文显示, 原因列在预览下方.
- 出错时: 语法错误与布局失败在预览下方给出行号, 预览保留上一次成功的布局并提示 "当前显示的是上一次成功的布局".
- 进入设计器: 已安装 3-Block Compose 1.2.0 或更高版本时, 预览面板上显示 "在 3-Block Compose 设计器中打开", 与 "更多" 菜单中的同名入口相同.

要编辑布局, 在画布上运行脚本, 或预览 `{{ }}` 以外的运行时数据, 使用设计器的 UI 工程 (见上文 "UI (XML) 工程").

## 限制

- 编辑时不运行脚本: 事件处理函数不会触发, `compose.state` 绑定在画布中显示初值或状态面板中的预览值, 渲染前置语句与条件 / 循环生成的内容只能以占位呈现. 1.5.0 起交互预览可以运行 JavaScript 工程的脚本, 但只提供 `compose`, 控制台与定时器等少数 API (见上文 "预览状态与交互预览" 一节).
- 弹层类组件 (`AlertDialog`, `ModalBottomSheet`, `DropdownMenu`, `Tooltip`) 处于打开状态时, 1.3.0 起按接近真实的样式画在画布的逻辑屏幕内 (对话框与底部弹层带遮罩盖在页面上方, 菜单与提示贴近锚点, 放不下时翻到另一侧), 不弹出真实窗口, 弹层中的节点可以点选; 菜单宽度取 112 - 280 dp 内的可用宽度, 不按内容收窄 (1.2.0 显示为内联卡片).
- `Image` (1.3.0): `'@drawable/名称'` 取自已安装的 AutoJs6, 相对路径在菜单 "图片目录" 选定的文件夹中查找; 网址, 绝对路径与表达式仍显示占位, 原因列在问题列表中. 1.2.0 中所有 `Image` 都显示占位.
- `AndroidView` 不能在设计器中绘制: 1.3.0 起显示为保留其尺寸修饰的浅色占位区域, 并在其中显示 `view` 表达式的源码; 不能从组件面板插入. `Snackbar` 是会话命令, 不在面板中.
- TSX 工程 (1.4.0) 与 TSX 的 UI 工程 (1.9.0) 需要 TypeScript Engine 0.7.0 或更高版本, 否则只能以只读源码查看与复制; 生成格式会把手写 TSX 的界面部分改写为统一格式 (见上文 "TSX 工程" 一节).
- 以 `file://` 路径打开的文件受系统存储限制, 可能无法读取或写回; 建议通过 AutoJs6 编辑器或文件管理器以内容 Uri 打开.
- UI (XML) 工程 (1.6.0) 的画布由 AutoJs6 的预览服务绘制, 需要 AutoJs6 6.8.0 及以上; 其它限制见上文 "UI (XML) 工程" 一节.
