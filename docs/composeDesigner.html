3-Block Compose 设计器 (Compose 与 UI 工程)#

3-Block Compose 设计器是 3-Block Compose 插件 (AutoJs6-Plugin-Three-Block-Compose) 自 1.2.0 起内置的可视化界面编辑器. 它在插件自己的进程中运行, 用插件的真实渲染器所见即所得地编辑 compose 脚本的界面树; 保存结果就是普通的 .js 脚本文件 (1.4.0 起也可以是 .tsx 文件), 可以交给 AutoJs6 运行, 也可以在 AutoJs6 编辑器中继续编写逻辑. 本页面自 3-Block Compose 1.2.0 起适用, 1.3.0 - 1.7.0 新增的能力在文中注明; 1.4.0 是插件的首个公开发行版.

本页面不是脚本 API. 设计器没有新增任何全局对象或模块, 它读写的脚本与手写的 compose 脚本完全相同. 脚本 API 见 3-Block Compose, 组件, 属性, 插槽与事件见 ComposeComponents.

用途#

  • 从组件面板拖放组件, 在画布上即时看到与 AutoJs6 内一致的渲染结果, 再在属性抽屉中调整属性, 修饰链, 插槽与事件.
  • 维护脚本的界面部分: 设计器只改写界面树和顶层 compose.state 声明, 其它语句原样保留, 因此可以反复在设计器与 AutoJs6 编辑器之间往返.
  • 编辑传统 "ui"; 模式脚本 (1.6.0): XML 布局在大纲与属性抽屉中编辑, 未触碰的字节原样保留, 画布由已安装的 AutoJs6 用 ui 模式的布局器绘制; 见下文 "UI (XML) 工程" 一节.
  • 编辑时设计器不执行脚本: 它只解析脚本 (JavaScript 用 Rhino 解析器, TSX 用 TypeScript Engine 插件的解析服务) 并用渲染器预览, 事件处理函数不会在画布中触发, 运行要交给 AutoJs6. 1.3.0 起可以在 "状态" 面板中临时改变 state 的预览值, 并在 "交互预览" 中直接操作绑定了 state 的控件; 1.5.0 起 JavaScript 工程的交互预览会在插件内受限的沙箱中运行脚本, 见下文 "预览状态与交互预览" 一节; 1.7.0 起 UI (XML) 工程的交互预览由 AutoJs6 真实运行整份脚本 (Android 13 起), 见 "在预览中运行 UI 脚本".

入口#

入口 说明
启动器图标 打开设计器首页 (工程列表). 右下角新建工程, 顶部栏进入组件画廊与设置页, 菜单中导入脚本文件. 设置页中的四种启动器图标都指向首页
AutoJs6 编辑器 "更多" 菜单中的 "在 3-Block Compose 设计器中打开". 需要包含该入口的 AutoJs6 6.8.0 构建 (宿主提交 db7e6a1734 之后); 已安装的插件低于 1.2.0 或未安装时不显示
文件管理器 以 3-Block Compose 打开 .js 文件 (application/x-javascript, text/javascript 或 text/plain); 1.4.0 起也可以打开 .tsx 文件 (另含 text/typescript). 1.6.0 起以 "ui"; 开头且调用 ui.layout 的 .js 文件按 UI (XML) 工程打开

从 AutoJs6 编辑器或文件管理器打开的文件直接在原位置编辑, 不会复制到设计器的工程目录.

工程与文件#

  • 工程就是一个 .js 文件 (1.4.0 起也可以是 .tsx 文件), 保存在插件私有目录 files/designer/projects/ 中, 没有额外的工程描述文件. 新建工程时选择 JavaScript, TSX (1.4.0) 或 UI (XML) (1.6.0), 写入一个最小的 compose.mount 模板 (UI 工程为 "ui"; 加一个带文本与按钮的 ui.layout 布局和一个点击处理函数); 名称重复时自动加 -2, -3 后缀. 导入的文件以 .tsx 结尾时成为 TSX 工程, 其它文件成为 .js 工程; .js 工程以 "ui"; 开头且调用 ui.layout 时按 UI (XML) 工程读取, 首页列表以 JS / TSX / UI 标注类型.
  • 导入: 通过系统文件选择器选择脚本, 复制为一个新工程并记录来源. 保存工程不会写回来源文件. 导出: 编辑页菜单 "导出到文件" 通过系统文件选择器另存一份.
  • 来源同步 (1.3.0): 导入时保留对来源文件的访问权限 (文件提供方允许时, 先尝试读写, 不行再只读), 之后可在编辑页菜单手动 "写回来源" 或 "从来源重新导入". 设计器记录双方上次同步时的内容摘要: 写回时来源在此之后被改过, 或重新导入时工程在此之后被改过 (含未保存修改), 都会先询问. 来源被移走, 被替换或授权失效时提示 "来源文件不可用", 可经系统文件选择器重新选择以恢复关联. 1.2.0 导入的工程没有摘要, 两侧内容相同时视为已同步.
  • 外部文档: 从 AutoJs6 编辑器或文件管理器打开的文件保存时直接写回原文件. 没有写入权限时 (例如只读授权或只读路径), 保存会把内容另存为一个新工程并提示, 编辑页随即切换到该工程, 原文件保持不变.
  • 草稿: 编辑停顿约 1 秒和离开编辑页时, 当前内容写入 files/designer/drafts/; 进程被结束后重新打开会询问恢复或丢弃草稿. 只有显式保存才写工程文件或原文件.
  • 外部修改: 回到编辑页时, 如果文件已被其它程序改写 (例如 AutoJs6 编辑器刚保存), 本地没有未保存修改时自动重新加载, 否则询问重新加载还是保留本地修改.
  • 图片目录 (1.3.0): 编辑页菜单 "图片目录" 为当前工程选择一个文件夹 (只读授权), Image 的相对路径 src 在其中查找并显示在画布上; 见下文 "限制" 一节.
  • 插件不申请存储权限. 工程目录只通过插件自己的内容提供器, 在 "在 AutoJs6 编辑器中打开" 与 "导入 AutoJs6 脚本目录" 时按次授权给 AutoJs6, 不暴露其它目录.

编辑页#

区域 内容
顶部栏 撤销, 重做, 保存; 菜单: 承载选项, 问题, 缩放 (75% / 100%), 复制脚本, 在 AutoJs6 中运行, 在 AutoJs6 编辑器中打开, 导入 AutoJs6 脚本目录, 导出到文件, 图片目录 (1.3.0), 写回来源与从来源重新导入 (1.3.0, 仅导入的工程), 组件画廊
画布 真实渲染器预览. 逻辑屏幕与画布视口同大, 对应 compose.mount 填满页面的效果; 点按选中节点, 长按拖到一个容器上, 按容器的排列方向 (纵向, 横向, 网格) 显示插入线, 放手后放在指针所在的位置 (1.3.0; 叠放类容器追加到末尾); 选中节点显示边框与 "类型 #key" 标签; 放大后可平移; 亮暗与主题色跟随设置页. 右上角 "交互预览" 开关见下文
大纲 多级折叠的节点树, 与画布选中同步. 每行提供上移, 下移, 删除; 长按拖动到另一节点的上方, 内部或下方可重排或换父, 是否能放入按目标组件的子节点策略判断
属性 选中节点的 key, 目录属性, 快捷属性 (padding, w, h 等), 插槽, 事件与修饰链
状态 (1.3.0) 顶层 compose.state 的初值与预览值, 见下文 "预览状态与交互预览" 一节
控制台 (1.5.0) 交互预览中脚本的 console / log 输出, toast 与错误, 见下文 "在预览中运行脚本" 一节; UI 工程 (1.7.0) 显示 AutoJs6 运行脚本的输出
组件面板 右下角 "+" 打开, 按组件画廊的分类列出全部可插入组件, 插入到当前选中的容器 (或根节点); 目标不接受子节点时提示

本节描述 Compose 工程的编辑页; UI (XML) 工程的画布, 面板与属性抽屉见下文 "UI (XML) 工程" 一节.

竖屏时画布在上, 大纲与属性在下; 横屏或平板上 (页面宽度大于高度) 画布在左, 大纲与属性在右. 大纲与属性列表的末尾留有空白, 可以把最后几行滚动到 "+" 按钮上方.

属性抽屉中每个属性有三种状态: 字面量 (布尔, 枚举, 文本样式, 形状, 颜色, 数值, 列表与字符串各有编辑器), 绑定已声明的 compose.state 变量, 或保留为源码表达式 (以代码框显示, 可改回字面量). 事件列表显示处理函数的参数与源码, 可以直接编辑, 应用前做语法检查; 新增事件时生成一个空的处理函数. 修饰链是有序列表, 支持增删, 上下移与逐项参数编辑, 1.3.0 起也可以按住每项左侧的手柄拖动排序 (一次拖动是一个撤销步骤); 只对特定父容器有效的修饰项按当前父容器过滤.

承载选项对话框切换 compose.mount, compose.floaty 与 compose.dialog, 并按键值编辑它们的选项对象 (值按脚本字面量填写, 例如 true, 320, 'rawText'). 问题对话框列出按组件目录校验出的错误与警告 (未知属性或事件, 值类型与范围, 修饰项作用域, 子节点策略, 重复 key, 契约上限等) 以及画布无法呈现的部分, 点击条目定位到节点.

全部编辑都进入撤销 / 重做历史; 连续修改同一属性合并为一步.

1.3.0 起画布每次编辑只重新组合发生变化的节点, 约 250 个节点的文档撤销 / 重做后的刷新明显更快.

预览状态与交互预览#

1.3.0 起编辑页有 "状态" 标签页, 画布右上角有 "交互预览" 开关; 1.5.0 起 JavaScript 工程的交互预览会运行脚本 (见下文 "在预览中运行脚本"). 两者都只改变画布, 不改动脚本, 也不产生撤销步骤或草稿.

  • 状态面板列出脚本顶层的每个 compose.state: 名称, 脚本中的初值 (字面量或表达式源码), 以及预览值. 布尔值用开关, 数字与字符串用输入框, 其它值 (数组, 对象, null, 或初值是表达式时) 按 JavaScript 字面量输入. 可以单项 "重置" 或 "全部重置"; 文档被重新加载 (外部修改, 从来源重新导入) 时预览值清空.
  • 画布中绑定了 state 的属性 (例如 checked: on.value) 显示预览值, 没有预览值时显示初值.
  • 打开 "交互预览" 后画布不再点选与拖动, 组件可以直接操作; 关闭开关即回到编辑模式. JavaScript 工程 (1.5.0 起, Android 8.0 或更高版本) 运行脚本, 见下一小节. TSX 工程, 以及 Android 8.0 以下设备上的工程, 不运行脚本: 一个绑定了 state 的属性, 如果组件有一个事件的载荷字段与该属性同名, 操作就把新值写入该 state 的预览值; 目前包括 Switch, Checkbox, RadioButton 的 checked, Slider 的 value, TextField / OutlinedTextField 的 text, FilterChip, InputChip, SegmentedButtonItem 的 selected, HorizontalPager 的 page, Tooltip 与 NavigationDrawer 的 open, SearchBar 的 expanded, DatePicker 的 selectedDateMillis 与 displayMode, TimePicker 的 hour 与 minute.

不运行脚本时 (编辑模式, TSX 工程, Android 8.0 以下) 与在 AutoJs6 中真实运行的差异:

  • 事件处理函数不执行. 按钮的 onClick, 以及处理函数中对 state 的其它赋值, 计算, toast, 模块调用等都不会发生; 只有上面那种 "控件的新值直接写回它绑定的 state" 会反映到预览值.
  • 只有直接写成 x.value 的属性参与; 表达式 (例如 selected: tab.value == 2 或 text: 'Hi ' + name.value) 不会随预览值重新计算, 文本类属性仍显示其源码.
  • 渲染函数不执行: 渲染前置语句, 条件与循环生成的内容仍是占位, 不会随预览值增减节点.
  • 弹层由打开状态的属性决定是否画在画布中; 画布中的弹层不会因点按遮罩或返回键而关闭, 要关闭可在状态面板改回预览值.
  • 预览值不随脚本保存, 也不会作为初值写回; 要改变初值, 在属性抽屉或 AutoJs6 编辑器中修改 compose.state(...).

在预览中运行脚本 (1.5.0)#

打开 "交互预览" 后, JavaScript 工程的脚本在插件内的沙箱中运行, 画布显示脚本挂载的界面. 运行的是保存时会写出的脚本, 状态面板中的预览值作为对应 compose.state(...) 的初值. 点击按钮, 输入文字, 拨动开关等事件交给脚本的处理函数, state 变化后渲染函数重新执行, 与在 AutoJs6 中运行时一样更新画布; 修改工程或预览值后脚本从头重新运行, 关闭开关后画布回到文档的预览. 脚本运行时, "交互预览" 开关上显示运行图标.

预览中可用的 API:

API 说明
compose / $compose state, ref, modifier, batch, memo, createElement 与全部节点工厂, mount / floaty / dialog (内容都画在画布上), post, theme, sessions, version, isAvailable, ComposeError; 节点句柄的属性读写与 set, get, append, insert, remove, replace, clear, slot, on, off, focus, blur, scrollTo, edit; 会话的 update, post, close, isClosed, on('close'), showSnackbar
console, log, print, toast, toastLog 写入 "控制台" 标签页; toast 与 showSnackbar 也只写入控制台
setTimeout, setInterval, clearTimeout, clearInterval 同时最多 64 个待执行的定时器, 重复间隔不小于 16 ms
JavaScript 标准内置对象 JSON, Math, Date, RegExp, Map, Set 等, 语言级别与 AutoJs6 的 Rhino (ES6) 一致

其它 AutoJs6 模块与全局函数 (app, ui, files, http, images, device, threads, sleep, require, importClass 等) 一经访问即抛出 "... is not available in the designer preview"; 需要 AutoJs6 ui 页面的 compose.attach 同样不可用. 脚本不能访问 Java 与 Android: java, Packages, android 等不可用, 也无法经任何对象取得 Java 类.

限制与差异:

  • 每次进入沙箱 (加载脚本, 处理一个事件, 执行一轮到期的定时器) 最多运行约 3 秒. 超出时 (例如死循环) 预览停止脚本, 画布底部与控制台说明原因; 修改工程, 或关闭再打开交互预览即可重新运行. 脚本中的 try / catch / finally 不能拦截这种停止.
  • 脚本错误 (未捕获的异常, compose 的参数错误) 显示在画布底部与控制台, 并列入问题列表; 预览继续运行, 之后的事件照常处理.
  • 文本框的输入按编辑序号同步: 用户已继续输入时, 脚本基于旧内容写入的文字不会覆盖它, 与在 AutoJs6 中一致.
  • compose.memo 在预览中每次都重新计算片段, 结果与 AutoJs6 相同, 只是不复用.
  • floaty 与 dialog 的窗口选项不生效, 内容画在画布上; AndroidView 无法在预览中创建视图, 仍显示占位.
  • 运行结果只用于画布: 不改动文档, 不写入工程或草稿, 预览中的 state 值也不会写回状态面板.
  • 设计器转到后台时停止脚本, 回到前台后重新运行.
  • 需要 Android 8.0 (API 26) 或更高版本 (沙箱中的 JavaScript Date 基于 java.time); 更低版本的设备与 TSX 工程按上文的方式预览, 不运行脚本.

可识别的脚本子集与往返规则#

设计器打开脚本时只解释下面两类顶层语句, 其余顶层语句 (require, 函数与变量定义, 事件注册, 注释等) 按源码范围原样保留, 位置不变:

  1. 顶层 state 声明: var / let / const x = compose.state(初值).
  2. 唯一的一处挂载调用: compose.mount(...), compose.floaty(...) 或 compose.dialog(...), 参数是返回界面树的渲染函数 (function () { return 树; } 或箭头函数) 或直接写出的节点, 可带选项对象; 渲染函数中 return 之前的语句作为渲染前置语句保留.

界面树内可识别: compose.X({属性}, 子节点...) 与子节点数组写法, 字符串子节点 (等价于 compose.Text), 快捷属性与 compose.modifier().a().b() 修饰链, key, 事件属性中的函数表达式 (源码保留), 以及对已声明 state 的 x.value 绑定. 属性值分三态: 字面量 (字符串, 数字, 布尔, null, 数组与对象字面量) 可在属性抽屉中编辑; x.value 识别为绑定; 其它表达式按源码保留, 画布中文本类属性显示其源码, 其它属性不参与预览. 条件或循环生成的子节点同样按源码保留, 画布中显示为占位.

以下情况无法映射, 设计器拒绝打开并给出行列位置: 语法错误, 没有挂载调用, 多处挂载调用, 根节点不是 compose 工厂调用, 渲染函数没有 return, 属性对象使用展开或计算键, 同一属性对象重复出现 children.

保存时按固定格式生成界面部分: 4 空格缩进, 字符串用单引号, 每个子节点独占一行. 设计器生成的脚本再次打开不会产生任何改动; 手写的脚本第一次保存时界面部分会被改写为该格式, 保留的语句与注释不变. TSX 工程见下一节 (1.2.0 与 1.3.0 不能打开 TSX 文件).

TSX 工程#

1.4.0 起设计器可以编辑 .tsx 工程. 新建工程时选择 "TSX", 或导入 .tsx 文件, 或从 AutoJs6 编辑器与文件管理器打开 .tsx 文件, 都按 TSX 读写.

  • 解析: 源码交给 TypeScript Engine 插件 0.7.0 或更高版本提供的语法树解析服务 (TypeScript 解析契约 v1), 只做语法分析, 不做类型检查, 不编译, 也不执行. TypeScript Engine 首次使用该服务时需要加载 TypeScript, 打开会慢几秒, 之后通常在 1 秒内.
  • 可识别的顶层语句与 JavaScript 相同 (顶层 state 声明与唯一的挂载调用), 界面树写成 JSX:
    • <compose.X> 与 <compose:X> 标签是可编辑的节点. key, modifier, 目录属性, 插槽 (属性值写成元素, 只含一个元素的 Fragment 或字符串), slots 与 children 属性, 以及 onXxx 事件属性中的函数都能识别.
    • 属性值: 引号字符串按 JSX 规则解码 &amp; 等实体, 不处理反斜杠转义; {} 中的字面量可在属性抽屉中编辑, {x.value} 识别为绑定, 其它表达式按源码保留; 不带值的属性 (例如 enabled) 等于 {true}.
    • JSX 文本子节点按 TypeScript 的 JSX 规则折叠空白, 解码实体后成为文本节点; {'文字'} 同样是文本节点.
    • Fragment (<>...</>) 被展开到所在位置; 根节点可以是只含一个 compose 元素的 Fragment.
    • 其它标签 (例如 const Increment = compose.Button 之后的 <Increment>) 与 {} 中的表达式子节点 (条件, 循环, 注释, 展开) 按源码保留, 画布中显示为占位.
    • compose.state<T>(初值) 的类型参数会保留; 带类型标注的变量 (例如 const n: number = <a href="http://man7.org/linux/man-pages/man0/compose.state.0.html">compose.state(0)</a>) 按普通语句原样保留, 不作为 state 显示. 带泛型, 返回类型, async 或函数名的事件函数按表达式保留.
  • 以下情况拒绝打开并给出行列位置: TypeScript 报告的语法错误, 与 JavaScript 相同的结构问题, XML 标签 (例如 <text>) 出现在 Compose 界面中, 展开属性 {...props}, 带命名空间的属性名, 带参数或类型参数的渲染函数, 挂载结果变量的类型标注, 超出 Unicode 范围的数字实体.
  • 生成格式: 4 空格缩进, 字符串属性用单引号 (例如 text='Hello'), 其它值写在 {} 中, 每个子元素独占一行; 没有子元素的元素自闭合, 只有一段纯文本的元素写在同一行 (例如 <compose.Button>Add</compose.Button>); 含单引号, &, 反斜杠或换行等不能原样写成 JSX 的字符串改写为 {'...'}; <compose:X> 写回为 <compose.X>. 设计器生成的 TSX 再次打开不会产生任何改动.
  • 事件处理函数的语法检查同样由 TypeScript Engine 完成, 可以使用类型标注等 TypeScript 语法.
  • 运行: "在 AutoJs6 中运行" 把工程文件以内容 Uri 交给 AutoJs6, AutoJs6 按文件名把它交给 TypeScript Engine 编译后运行 (JavaScript 工程仍交出脚本文本); 有未保存修改时先保存. 复制, 导出 (保持 .tsx 文件名), 在 AutoJs6 编辑器中打开与导入 AutoJs6 脚本目录与 JavaScript 工程相同.
  • 未安装 TypeScript Engine, 版本低于 0.7.0, 或解析服务暂时不可用时, TSX 工程以只读方式显示源码并说明原因: 可以复制源码或重试, 不能编辑界面树, 也没有画布预览. 安装或更新 TypeScript Engine 后回到设计器会自动重试.

UI (XML) 工程 (1.6.0)#

1.6.0 起设计器可以打开传统 "ui"; 模式脚本 (布局写成 E4X XML 字面量, 见 ui) 并作为 "UI (XML) 工程" 编辑. 新建工程时选择 "UI (XML)", 或导入这样的脚本, 或从 AutoJs6 编辑器与文件管理器打开它, 都按 UI 工程读写; 首页列表以 UI 标注. 画布不由插件自带的渲染器绘制, 而是交给已安装的 AutoJs6 (见下文 "布局预览").

可识别的脚本子集#

  • 脚本以 "ui"; 指令开头 (前面可以有注释), 并至少调用一次 ui.layout(...).
  • 脚本中的每个 XML 字面量都是一个布局片段: ui.layout 的参数 (直接写出的字面量, 或只被一个 XML 字面量初始化且之后不再赋值的变量) 是画布默认显示的根; 其它字面量 (例如 ui.inflate 的模板) 可以在大纲顶部的片段切换器中切换到画布.
  • ui.registerWidget(名称, ...) 注册的自定义控件标签按脚本的约定接受任意属性, 不参与目录校验.
  • 其它顶层语句 (函数, 变量, 事件注册, require 等) 全部按源码原样保留, 位置不变. 设计器只读写 XML 字面量, 以及 (见下文 "事件") 在 ui.layout 语句之后追加的处理函数桩.
  • 以下情况拒绝打开并给出行列位置: 语法错误, 没有 "ui" 指令, 没有 ui.layout 调用, ui.layout 的参数既不是 XML 字面量也不是只用一个字面量初始化的变量, 嵌套的 XML 字面量, XML 列表 (<>...</>), 字面量本身的 XML 语法问题.

无损写回#

XML 字面量以带位置的具体语法树保存: 空白, 注释, CDATA, 处理指令, 属性顺序, 引号与 E4X {表达式} 片段全部保留, 保存时未触碰的字节不变. 只有被编辑过的开始标签 (改属性或标签名时整个开始标签重排, 未改的属性保持原文与引号, 新属性追加在末尾, 新 id 写在最前), 被修改的文本内容, 以及新插入的元素会被改写; 新元素按相邻元素的缩进生成并自闭合, 删除元素时连带其前面的空白行. 与 Compose 工程不同, UI 工程没有 "规范格式": 手写的脚本第一次保存也不会被整体重排.

编辑页#

区域 内容
画布 由 AutoJs6 绘制的布局 (见下文 "布局预览"); 点按选中元素 (命中最小的可见元素), 长按拖到另一元素上按容器方向插入; 选中框与 "标签 #id" 标签; 缩放 75% / 100%. 画布上方一行放 "交互预览" 开关与运行状态 (1.7.0, 见下文 "在预览中运行 UI 脚本")
大纲 元素树: 折叠, 上移 / 下移 / 删除, 长按拖动到另一元素的上方 / 内部 / 下方; 脚本有多个 XML 字面量时顶部显示片段切换器, 传给 ui.layout 的片段标 "(ui.layout)"
属性 标签 (可换成面板中的任一标签), id, 文本内容 (没有元素子节点的元素), 已设置的属性 (按脚本顺序置顶), 按 View 类分组的目录属性 (最近的类展开, 简写属性在名下显示全名), 值三态, 裸属性, 任意属性名, 事件 (见下文)
绑定 当前片段中 {{ }} 引用的名称: 脚本顶层字面量声明的求值结果 (var title = "Hi" 这类不运行脚本也能求出的声明, 在插件的沙箱中求值, Android 8.0 或更高版本), 求值失败的原因, 或 "无顶层声明"; 可以输入 JSON 覆盖值, 只影响画布, 不进文档, 撤销与草稿
问题 按文档站的标签与属性目录校验: 未知标签, 未知或宿主拒绝的属性, 值的类型与格式 (布尔, 整数, 尺寸, 颜色, gravity, 枚举), 只对 relative 子视图有效的属性, list / grid 的模板子节点, 重复 id, 空的 {{ }}; 以及布局预览的失败与诊断
控制台 布局预览时显示预览的状态与 AutoJs6 绘制时报告的失败码, 位置与诊断; 交互预览 (1.7.0) 时显示 AutoJs6 运行脚本的输出, 错误与结束原因
组件面板 右下角 "+": 文档站的 48 个标签按布局 / 文本 / 按钮 / 输入 / 选择 / 进度 / 图片 / 媒体 / 列表 / 其它分类, 每个带默认属性; 插入到选中的容器末尾, 或选中元素之后. <compose> 容器与类名标签不在面板中, 脚本里已有的仍可编辑

属性值分三态: 文本 (实体在编辑器中已解码, 布尔属性是开关, 枚举属性是下拉), {{ 表达式 }} 绑定 (编辑花括号内的表达式, 或从顶层声明中选择; 文本与绑定混合的值编辑原文), 以及 E4X {表达式} (脚本运行时才有值, 只读显示源码, 可整个换成文本). 行菜单在三态之间切换, 把布尔属性写成裸属性 (<console global>), 或删除属性. 自由添加的属性名不在目录中时由问题列表提示, 宿主会忽略它.

事件#

事件处理函数不在设计器中编写. 属性抽屉的 "事件" 区按标签列出事件 (所有视图: click, long_click, touch, key; 复合按钮另有 check; list / grid 另有 item_click, item_long_click, item_bind; canvas 另有 draw), 点 "添加" 后在该布局所属的 ui.layout(...) 语句之后 (紧随脚本已写在那里的处理函数之后) 追加:

ui.ok.on('click', () => {
    // TODO
});

元素没有 id 时先按标签补一个 (button1), 与追加桩是同一个撤销步骤. 桩写入后就是普通源码: 设计器不再展示或修改它, 正文在 AutoJs6 编辑器中写; 脚本已经用 ui.<id>.on(...) 或 .click(...) / .longClick(...) 注册过的事件显示为 "脚本中已处理". 只有以语句形式传给 ui.layout 的布局能添加事件 (return ui.layout(...) 与表达式体的箭头函数不行).

布局预览#

UI 工程的画布由已安装的 AutoJs6 绘制: 设计器把当前片段的 XML 文本 (E4X {表达式} 换成求得的值或源码) 与 {{ }} 的绑定值交给 AutoJs6 的预览服务, AutoJs6 用 ui 模式的布局器 (与 ui.layout 相同) 创建真实视图并画出来, 每个元素的位置回传给设计器用于点选与高亮. 不运行工程的脚本.

条件 行为
AutoJs6 包含预览服务 (宿主提交 306a8f7834 之后的 6.8.0 构建), Android 11 (API 30) 或更高版本 画布嵌入 AutoJs6 绘制的真实视图, 编辑后约几十毫秒刷新
同上, Android 7.0 - 10 AutoJs6 把布局画成位图传回, 画布显示快照
未安装 AutoJs6, 或 AutoJs6 没有预览服务 画布显示原因 (缺少 AutoJs6 或版本过旧), 工程仍可编辑, 大纲与属性抽屉照常
  • 画布的逻辑屏幕与视口同大, 对应 ui.layout 填满页面的效果; 亮暗与语言跟随设置页.
  • 布局失败 (XML 无法解析, 标签或属性被宿主拒绝, 某个 View 在测量时出错) 时画布说明原因, 问题列表与大纲定位到出错的元素; {{ }} 求值失败的属性按原文显示, 作为诊断列出.
  • 预览运行时是 AutoJs6 内的一次 ui 模式执行, 以 "3-Block Compose 预览" 出现在 AutoJs6 的运行列表中, 可以从那里停止 (画布会提示, 回到设计器时重新连接); 设计器关闭或转到后台时释放.
  • 布局预览只用于布局: 不响应控件的点击与输入 (编辑模式拦截指针), 窗口级函数 (ui.statusBarColor 等) 与弹出层不生效, WebView, VideoView, SurfaceView 类视图在快照模式下显示占位. 要在画布上真实运行脚本, 见下节 "在预览中运行 UI 脚本" (1.7.0).

在预览中运行 UI 脚本 (1.7.0)#

画布上方的 "交互预览" 开关打开后, AutoJs6 会把整份脚本当作一次普通的 ui 模式运行来执行 (与 "在 AutoJs6 中运行" 相同的引擎, 相同的权限), 只是 ui.layout 的内容显示在设计器的画布上而不是 AutoJs6 的页面里. 画布里的控件直接接收点击与触摸, 脚本的事件处理函数, {{ }} 绑定, 定时器与其它 AutoJs6 模块都按脚本的逻辑真实运行; 控制台标签页显示脚本的 console 输出, 错误与结束原因. 每个工程第一次打开开关时会先确认: 这等价于运行脚本, 脚本的副作用 (文件, 网络, 无障碍操作, 悬浮窗等) 都会真实发生.

条件 行为
AutoJs6 包含预览契约 v2 (宿主提交 4c332c2053 之后的 6.8.0 构建), Android 13 (API 33) 或更高版本 显示 "交互预览" 开关; 打开后 AutoJs6 在画布中运行脚本, 开关上显示运行图标
Android 13 - 14 同上, 但画布中的输入框收不到键盘输入 (提示 "Android 15 之前预览不能接收键盘输入"); Android 15 起输入法可用
Android 7.0 - 12, 或 AutoJs6 只有预览契约 v1 (1.6.0 配套的构建) 不显示开关, 画布上方说明原因 (需要 Android 13 / 需要更新的 AutoJs6), 用 "在 AutoJs6 中运行" 试运行脚本
  • 运行的是保存时会写出的脚本; 绑定值面板中的临时覆盖只影响布局预览, 真实运行使用脚本自己的值.
  • 修改工程后约 0.4 秒脚本从头重新运行; 关闭开关, 设计器转到后台或关闭编辑页时脚本停止, 画布回到布局预览. 脚本调用 exit() 或出错后结束时, 画布上方与控制台显示原因 (错误带行号), 开关保持打开, 修改工程或关闭再打开开关即可再次运行.
  • 运行以工程文件名出现在 AutoJs6 的运行列表中, 也可以从那里停止.
  • 运行结果只用于画布: 不改动文档, 不写入工程或草稿. 交互期间画布不再响应点选与拖拽 (指针交给脚本的控件), 大纲与属性抽屉照常可用.
  • 与在 AutoJs6 中运行的差异: 没有 Activity 窗口, activity 为 undefined, ui.finish, ui.statusBarColor 等窗口级函数不生效 (控制台各提示一次), ui.emitter 只有 create; 画布的逻辑屏幕与视口同大, 没有状态栏 / 导航栏; dialogs.* 等对话框以悬浮窗形式显示在设计器之上 (需要 AutoJs6 的悬浮窗权限). 脚本体与处理函数和真实运行一样在 AutoJs6 的主线程执行, 忙等 (例如 while (true)) 会卡住 AutoJs6, 停止也要等它让出; 定时器与事件驱动的脚本可随时停止.
  • 与 JavaScript (Compose) 工程的交互预览不同, UI 工程的脚本不在插件内的沙箱里运行, 而是真实地在 AutoJs6 中运行, 没有 API 范围与时间限制; 不要在预览中运行会产生不可逆副作用的脚本.

限制#

  • 只识别 "ui" 指令与 XML 字面量; 用字符串拼接或运行时才生成的布局不在画布中.
  • 布局预览不运行脚本: {{ }} 只能显示顶层字面量声明或绑定值面板给出的值; 列表项模板中的 {{ }} 没有数据源, 按原文显示. 交互预览 (1.7.0, Android 13 起) 运行整份脚本后这些都按脚本的逻辑显示.
  • 布局预览需要 AutoJs6 的预览服务; 旧版本 AutoJs6 只能编辑, 不能预览.
  • 属性目录来自文档站 (ui 与 uiAttributes 页面, 生成时的文档提交记录在目录中), 文档未收录的属性按 "未知属性" 提示而不是拒绝.

与 AutoJs6 的衔接#

编辑页菜单提供四个去向, 都复用 AutoJs6 的公开入口, 需要已安装 AutoJs6; 去向前如有未保存修改会先保存:

去向 行为
在 AutoJs6 中运行 把脚本文本交给 AutoJs6 运行, 与组件画廊的 "运行" 相同; TSX 工程 (1.4.0) 交出工程文件, 见上文 "TSX 工程" 一节
在 AutoJs6 编辑器中打开 以内容 Uri 和读写授权在 AutoJs6 编辑器中打开同一文件; AutoJs6 保存后回到设计器会自动重新加载
导入 AutoJs6 脚本目录 AutoJs6 以文件名把脚本复制到自己的脚本目录
复制脚本 复制到剪贴板

反向交接由 AutoJs6 编辑器发起: "在 3-Block Compose 设计器中打开" 先保存当前文件, 再以读写授权交给设计器; 设计器保存后回到 AutoJs6 编辑器, 编辑器按文件内容是否变化自动重新加载, 存在未保存修改时先询问. 该菜单项需要包含对应入口的 AutoJs6 6.8.0 构建 (宿主提交 db7e6a1734 之后); 其它去向只需要能运行 compose 脚本的 AutoJs6 (宿主提交 f12665ffde 之后).

设计器本身不依赖 AutoJs6: 画布使用插件自带的渲染器, 与脚本在 AutoJs6 内运行时的渲染实现相同.

限制#

  • 编辑时不运行脚本: 事件处理函数不会触发, compose.state 绑定在画布中显示初值或状态面板中的预览值, 渲染前置语句与条件 / 循环生成的内容只能以占位呈现. 1.5.0 起交互预览可以运行 JavaScript 工程的脚本, 但只提供 compose, 控制台与定时器等少数 API (见上文 "预览状态与交互预览" 一节).
  • 弹层类组件 (AlertDialog, ModalBottomSheet, DropdownMenu, Tooltip) 处于打开状态时, 1.3.0 起按接近真实的样式画在画布的逻辑屏幕内 (对话框与底部弹层带遮罩盖在页面上方, 菜单与提示贴近锚点, 放不下时翻到另一侧), 不弹出真实窗口, 弹层中的节点可以点选; 菜单宽度取 112 - 280 dp 内的可用宽度, 不按内容收窄 (1.2.0 显示为内联卡片).
  • Image (1.3.0): '@drawable/名称' 取自已安装的 AutoJs6, 相对路径在菜单 "图片目录" 选定的文件夹中查找; 网址, 绝对路径与表达式仍显示占位, 原因列在问题列表中. 1.2.0 中所有 Image 都显示占位.
  • AndroidView 不能在设计器中绘制: 1.3.0 起显示为保留其尺寸修饰的浅色占位区域, 并在其中显示 view 表达式的源码; 不能从组件面板插入. Snackbar 是会话命令, 不在面板中.
  • TSX 工程 (1.4.0) 需要 TypeScript Engine 0.7.0 或更高版本, 否则只能以只读源码查看与复制; 生成格式会把手写 TSX 的界面部分改写为统一格式 (见上文 "TSX 工程" 一节).
  • 以 file:// 路径打开的文件受系统存储限制, 可能无法读取或写回; 建议通过 AutoJs6 编辑器或文件管理器以内容 Uri 打开.
  • UI (XML) 工程 (1.6.0) 的画布由 AutoJs6 的预览服务绘制, 需要包含该服务的 AutoJs6 6.8.0 构建 (宿主提交 306a8f7834 之后); 其它限制见上文 "UI (XML) 工程" 一节.
